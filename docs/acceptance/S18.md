# S18 — Check for updates & release 0.1.0 — acceptance criteria

Sunshot tells the user when a newer version is published. It asks the release feed (GitHub's "latest release" of
`pqBrain/SunShot`) for the newest version number: from Sunshot ▸ Check for Updates…, from the menu bar menu, from
Settings ▸ About ▸ Check Now, and automatically once a day. It never downloads or installs anything itself: Download
opens the release page. This slice also cuts the first public release, 0.1.0.

## S18-AC1 — Version ordering
Given two release versions (`0.1.0`, `v0.2`, `1.0.0-beta.2`, `1.0.0+42`)
Then they compare the semantic-versioning way: numbers numerically, missing parts as 0, a pre-release before its
release, build metadata ignored; text that is not a version (`dev`, `__VERSION__`, `1..2`) is not read as one
Test level: unit

## S18-AC2 — Reading the release feed
Given the feed's latest release
Then Sunshot reads its version (tag), title (or `Sunshot <version>` when untitled), notes, release page and the
attached `.zip` / `.dmg`; drafts and pre-releases are never offered; unreadable answers are refused; long notes are
cut at a line break for the alert
Test level: unit

## S18-AC3 — Check for Updates…
Given Sunshot ▸ Check for Updates… (also in the menu bar menu and Settings ▸ About ▸ Check Now)
Then the check always answers: "Sunshot X is available" (Download · Later · Skip This Version) when the release is
newer than the running version, "You're up to date" otherwise (a development build is always up to date), "No
releases yet" when nothing is published, and "Couldn't check for updates" when offline or the server fails; the
item has no key equivalent and is disabled while a check runs; two checks at once share one request
Test level: unit

## S18-AC4 — Automatic daily check
Given Settings ▸ About ▸ Check for updates automatically (on by default, saved with the other settings)
Then while it is on, Sunshot checks at launch and while it keeps running, at most once a day; a check that failed
is retried later and never shows anything; an automatic check speaks up only for a new version; while it is off
nothing is sent
Test level: unit

## S18-AC5 — Skip This Version
Given the update alert for version X
When the user chooses Skip This Version
Then automatic checks stay quiet about X (also after relaunch), a newer version than X is announced again, and
Check for Updates… still shows X
Test level: unit

## S18-AC6 — Privacy
Given any update check
Then the only request is a GET to the release feed carrying the `Sunshot/<version>` user agent and an Accept header:
no identifiers, document content or settings; Settings ▸ About ▸ Privacy says Sunshot asks GitHub for the latest
version number
Test level: unit

## S18-AC7 — Updates in Settings ▸ About
Given Settings ▸ About
Then an Updates card shows what the last check found and when ("Up to date · checked today at 10:42", "Not checked
yet", "Checking for updates…"), a Check Now button and the automatic-check switch
Test level: unit

## S18-AC8 — Release 0.1.0
Given the repository at the release commit
Then `VERSION` is `0.1.0` (not a pre-release), the app bundle reports it in Finder and Settings ▸ About, and
`make release` builds `dist/Sunshot-0.1.0.zip` with its SHA-256 for the GitHub release
Test level: unit

## S18-AC9 — Update alert and About card look right
Given the update alert (new version, up to date, no releases, couldn't check) and the About tab's Updates card
Then they read well in Light and Dark, the alert comes forward even when only the menu bar icon is showing, and
Download opens the release page in the browser
Test level: manual
