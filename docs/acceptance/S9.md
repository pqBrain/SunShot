# S9 — Annotate — acceptance criteria

Conventions: tools = `select | pen | highlighter | eraser | arrow | rectangle | text | step | redact | sticker` with
shortcuts V, P, H, E, A, R, T, S, B and (sticker picker) ⌥⌘S. Annotations are vector objects stored in the document
(`Project.annotations`) in **content-pixel coordinates** (origin at the top-left of the unscaled content image, y down),
so they stay attached to the content when canvas size, padding or exact-size scaling change. Each annotation has
a colour (sRGB), a line width in content pixels, a line style `solid | dashed | dotted`, a fill flag (rectangles), a
rotation in degrees about its bounds centre, and kind-specific data (points, text, emoji, redaction mode). Sizes
S / M / L are 3 / 6 / 12 px for content whose long edge is ≤ 1000 px and scale with the long edge above that.
Selection is editor state, never an undo entry. Every document change is exactly one undo entry per gesture.

## S9-AC1 — Annotate mode and tool palette
Given a document with content
When Annotate mode is entered (toolbar button or ⇧⌘A)
Then a tool palette shows Select, Pen, Highlighter, Eraser, Arrow, Rectangle, Text, Steps, Redact and Sticker, each with
its shortcut in the help text, plus colour, size, line style, fill and Clear controls
And pressing a tool's letter selects it, and Esc leaves Annotate mode (clearing the selection)
And without content Annotate mode cannot be entered
Test level: unit

## S9-AC2 — Annotations persist in the document with tolerant decoding
Given a project with annotations of every kind
When it is encoded and decoded
Then the decoded project is equal to the original
And a project JSON without an annotations key decodes with no annotations, an annotation with an unknown kind is
skipped while the others decode, and a missing optional field takes its default
Test level: unit

## S9-AC3 — No annotations changes nothing
Given a document without annotations (or whose annotations were all cleared)
When rendered
Then the output is byte-identical to the render before S9 (the S1 default snapshot still matches)
Test level: snapshot

## S9-AC4 — Annotations stay attached to the content
Given a rectangle annotated at content pixels (100, 100)–(200, 150)
When padding changes from 64 to 200, or the canvas becomes an exact size that scales the content
Then the rectangle is drawn at the same place on the content in every render (its canvas position = content origin +
content point × style scale)
Test level: unit

## S9-AC5 — Preview ↔ content coordinate mapping
Given a preview of the canvas displayed at any size
When a point in the preview is converted to content coordinates and back
Then the round trip returns the same point (±0.001), the mapping accounts for padding, exact-size scaling and the
displayed size, and points outside the content are reported as outside
Test level: unit

## S9-AC6 — Pen draws a smoothed freehand stroke
Given the Pen tool, colour red, size M, line style solid
When the pointer is dragged through several points
Then one pen annotation with those points (consecutive duplicates dropped) is added as a single undo entry "Draw"
And it renders as a smooth, round-capped stroke of the chosen width; dashed and dotted styles render as dashes / dots
Test level: snapshot

## S9-AC7 — Highlighter is a wide, translucent, multiplied stroke
Given the Highlighter tool
When a stroke is drawn over white and over black content
Then it is three times the pen width, over white it shows a tint of the colour, and over black it stays black (multiply)
And the whole stroke is a single undo entry "Highlight"
Test level: unit

## S9-AC8 — Eraser removes whole objects
Given several annotations
When the eraser is dragged across two of them
Then exactly those two are removed (never part of a stroke) as a single undo entry "Erase"; dragging over nothing
records nothing
Test level: unit

## S9-AC9 — Arrow
Given the Arrow tool
When the pointer is dragged from A to B
Then an arrow from A to B with a filled head at B is added ("Add Arrow"); the head scales with the line width
And a selected arrow has two endpoint handles that move each end independently, as one undo entry per drag
And a click without a drag adds nothing
Test level: snapshot

## S9-AC10 — Rectangle, outline or filled
Given the Rectangle tool
When the pointer is dragged diagonally (in any direction)
Then a rectangle spanning the drag is added ("Add Rectangle"), drawn as an outline in the line style, or filled when
Fill is on
Test level: snapshot

## S9-AC11 — Text
Given the Text tool
When the canvas is clicked, text is typed and committed
Then a text annotation with that text, in the current colour, at a font size derived from the size (S/M/L) is added as
one undo entry "Add Text"; committing empty text adds nothing
And double-clicking a text annotation with Select edits it ("Edit Text"); multi-line text and left / centre / right
alignment are supported
Test level: snapshot

## S9-AC12 — Step counter numbers itself
Given the Steps tool
When the canvas is clicked three times
Then steps 1, 2, 3 are added (one undo entry "Add Step" each), drawn as filled circles with a contrasting number
And deleting step 2 renumbers step 3 to 2; with the Letters format they read A, B, C
Test level: unit

## S9-AC13 — Redaction destroys the underlying pixels
Given content with fine detail (one-pixel lines) and a Redact rectangle over it in Pixelate or Blur mode
When the document is exported (any scale)
Then no pixel inside the region keeps the original detail: the redaction is computed from block averages of the
content (block ≥ 8 content px), so the original values cannot be recovered from the export
And the preview shows the same redaction (same render call)
Test level: unit

## S9-AC14 — Emoji stickers
Given the sticker picker (⌥⌘S or the palette)
When an emoji is picked and the canvas clicked
Then the emoji is placed as a sticker annotation ("Add Sticker") at a size derived from the size setting, and it can be
moved, resized and rotated like any other object
Test level: snapshot

## S9-AC15 — Colour, size and line style
Given the palette
Then it offers Sunshot's 20 annotation colours (5 neutrals, 15 hues) and a custom colour
And `[` / `]` step the size down / up through S, M, L; ⇧1 / ⇧2 / ⇧3 pick solid / dashed / dotted; F toggles fill
And changing any of these while objects are selected applies it to them as one undo entry
Test level: unit

## S9-AC16 — Selection and hit-testing
Given overlapping annotations
When the Select tool clicks on them
Then the topmost annotation under the pointer (within a tolerance of 6 screen points, rotated objects tested in their
own frame) is selected; ⌘-click adds or removes objects from the selection; clicking empty space clears it
Test level: unit

## S9-AC17 — Move, resize and rotate
Given a selection
When it is dragged, a corner handle is dragged, or the rotate handle is dragged
Then the selected objects move together ("Move Annotation"), the object resizes from the opposite corner, which stays
fixed even when rotated ("Resize Annotation"), or rotates about its centre ("Rotate Annotation"), with ⇧ snapping
rotation to 15°; each drag is exactly one undo entry and a click that does not move records nothing
Test level: unit

## S9-AC18 — Duplicate, delete, clear
Given a selection
When ⌘D, ⌫ or ⌘⌫ (in Annotate mode) is pressed
Then the selection is duplicated with an offset and the copies become the selection ("Duplicate Annotation"), deleted
("Delete Annotation"), or all annotations are cleared ("Clear Annotations"); each is one undo entry and undo restores
the previous annotations exactly
Test level: unit

## S9-AC19 — Vector at export resolution
Given a pen stroke of width 6 content px on 1000×600 content
When exported at 1× and 2×
Then the stroke is 6 and 12 pixels wide respectively with anti-aliased edges (no upscaled bitmap), and the preview uses
the same render call
Test level: unit

## S9-AC20 — Annotate mode looks right and is accessible
Given the running app
Then the tool palette uses the glass look in Light and Dark, the selected tool is marked, VoiceOver reads each tool
with its shortcut, the selection outline and handles follow the object (incl. rotation), and drawing feels immediate
Test level: manual

## Open questions
- Annotations span the whole canvas in the reference; Sunshot draws them inside the content (clipped to its corner
  shape) so they move with the content. **Decided** for S9; revisit if users need callouts on the padding.
- Replacing the content image keeps the annotations at their content-pixel positions. **Decided.**
- Font family follows the system font until S5's font tokens land. **Decided.**
