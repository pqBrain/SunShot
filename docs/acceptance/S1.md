# S1 — Walking skeleton: import → canvas → export — acceptance criteria

Conventions for this slice: "content" is the imported image at its native pixel size W×H. Default padding P = 64 px on every side, so the default canvas is (W+128)×(H+128) px and export at the default scale is 1 canvas px = 1 output px. Default backdrop = solid colour #EDEDF2. All of these live in one `SunshotDefaults` constant so tests reference it rather than literals.

## S1-AC1 — Empty state shown on launch
Given the app launches with no document content
When the main window appears
Then the canvas area shows a drop zone with the text "Drop an image here", a "Choose Image…" button, and a hint "or press ⌘V to paste"
And Export, Copy PNG and Clear are disabled
And Undo and Redo are disabled
Test level: app-smoke

## S1-AC2 — Open image via file picker for every readable format
Given the empty state
When the user chooses a valid PNG, JPEG, HEIC, TIFF or WebP file through "Choose Image…" (or File ▸ Open Image… ⌘O)
Then the content is decoded and the document model holds content of the file's pixel size W×H
And the empty state is replaced by the canvas preview
And the decode succeeds for each of the five formats in the fixture set
Test level: integration

## S1-AC3 — Unsupported or corrupt file rejected without state change
Given a document in any state (empty or with content)
When the user opens a 0-byte file, a truncated PNG, a text file renamed `.png`, or a PDF
Then no content is changed
And an alert titled "Can't open this file" is presented with the file name and a one-line reason
And the undo stack length is unchanged
Test level: unit

## S1-AC4 — Drag-and-drop import
Given the main window is open
When the user drags a single supported image file from Finder onto the canvas or drop zone
Then the drop zone highlights while the drag is over it and the image is imported as in S1-AC2
And when several files are dropped, only the first supported file is imported and a non-blocking notice says "Only one image is supported for now"
And when a non-image file is dropped the drop is refused (no highlight, no state change)
Test level: manual

## S1-AC5 — Paste image with ⌘V
Given the pasteboard holds image data (PNG, TIFF, or an image file URL) 
When the user presses ⌘V or chooses Edit ▸ Paste
Then the image becomes the content, exactly as in S1-AC2 (S15: when image content is already open, a paste is
added as the next screenshot instead — see S15-AC10)
And when the pasteboard holds no image, Paste is disabled and nothing changes
Test level: integration

## S1-AC6 — Default canvas composition
Given content of size 1000×600 has been imported
When the preview is rendered
Then the canvas size is exactly 1128×728 px
And the backdrop is a solid fill of the default colour #EDEDF2
And the content is placed with its top-left at (64, 64) with no scaling
And the rendered image matches the approved snapshot `s1-default-1000x600`
Test level: snapshot

## S1-AC7 — Padding is applied symmetrically for any content size
Given content of sizes 1×1, 16×16, 1000×600, 600×1000 and 8000×8000
When each is rendered
Then the canvas sizes are 129×129, 144×144, 1128×728, 728×1128 and 8128×8128 px respectively
And the content rect is always centred with 64 px margin on all four sides
Test level: unit

## S1-AC8 — Transparent PNG content keeps its alpha over the backdrop
Given a PNG with a fully transparent region and a 50 %-alpha region is imported
When the canvas is rendered
Then pixels in the transparent region equal the backdrop colour #EDEDF2 exactly
And pixels in the 50 % region equal the 50/50 blend of content colour and backdrop (±1 per channel)
And the exported PNG still has an alpha channel (a fully opaque backdrop makes all output alpha = 255)
Test level: snapshot

## S1-AC9 — Orientation and colour space are honoured on import
Given a JPEG with EXIF orientation 6 (rotated 90° CW) and a Display P3 PNG
When each is imported
Then the model's content size reflects the displayed (rotated) orientation
And colours are converted to sRGB for rendering so that a P3 sample pixel renders within ΔE ≤ 2 of the reference value
Test level: unit

## S1-AC10 — Export PNG via save panel (⇧⌘E)
Given content is loaded
When the user presses ⇧⌘E (or File ▸ Export PNG…)
Then a save panel opens with the suggested file name `sunshot-<yyyy-MM-dd_HH-mm-ss>.png` (final template arrives in S4) and the Pictures folder as the initial location
And on confirmation a valid PNG is written whose pixel size equals the canvas size from S1-AC6/AC7
And cancelling the panel writes nothing and changes no state
Test level: integration

## S1-AC11 — Export write failure surfaces an error
Given content is loaded and the chosen destination is read-only or the disk is full
When export is confirmed
Then no partial file remains at the destination
And an alert "Couldn't export the image" with the system reason is shown
And the document is still intact and editable
Test level: integration

## S1-AC12 — Copy PNG with ⌘C
Given content is loaded
When the user presses ⌘C (or Edit ▸ Copy, or clicks "Copy PNG")
Then the general pasteboard contains exactly one PNG representation of the full canvas at the same pixel size as the export
And the pasted bytes decode to an image pixel-identical to the exported PNG
Test level: integration

## S1-AC13 — Preview/export pixel parity
Given content of 1000×600 and a transparent PNG of 640×480
When the preview render function and the export render function are each asked for the canvas at 1× 
Then both call the same `render(document:scale:)` entry point (enforced by an architecture check: no second drawing path)
And the two bitmaps are byte-identical in sRGB 8-bit RGBA
Test level: unit

## S1-AC14 — Clear content
Given content is loaded
When the user chooses Clear (toolbar button or Edit ▸ Clear Content)
Then the document returns to the empty state of S1-AC1
And Clear is itself undoable: Undo restores the same content, Redo clears it again
Test level: unit

## S1-AC15 — Single document store with undo/redo for every mutation
Given a document store with an empty undo stack
When the mutations "import image", "replace image with a second image" and "clear content" are applied in order
Then the undo stack has 3 entries, each with a human-readable name ("Import Image", "Replace Image", "Clear Content")
And ⌘Z three times restores empty → image 2 → image 1 → empty state in reverse, and ⇧⌘Z replays them in order
And a new mutation after an Undo discards the redo stack
And all views read state only from this store (no secondary copies of content), proven by an architecture check
Test level: unit

## S1-AC16 — Importing over existing content replaces it
Given content A is loaded
When the user imports or drops image B (a paste adds a screenshot instead, S15-AC10)
Then B replaces A without a confirmation dialog, and a single Undo brings A back
Test level: unit

## S1-AC17 — Large image (8000×8000) import, render and export within resource budgets
Given an 8000×8000 opaque PNG
When it is imported, previewed and exported
Then the preview stays responsive (main thread never blocked > 100 ms; decode happens off-main with a progress indicator after 250 ms)
And the exported PNG is 8128×8128 px
And peak resident memory growth during export is ≤ 1.5 GB
And no crash occurs when exporting twice in a row
Test level: integration

## S1-AC18 — Render time budget for 4K output
Given a 3712×2032 content image (canvas = 3840×2160 px)
When the export render function is invoked on Apple silicon in a release build
Then the median of 10 runs completes in ≤ 500 ms (excluding file encoding)
Test level: integration

## S1-AC19 — Light and dark appearance
Given the system appearance is Light, then Dark
When the empty state and the loaded-canvas window are shown
Then all text meets WCAG AA contrast (≥ 4.5:1) against its background in both appearances
And the exported image is identical in both appearances (the canvas content does not depend on app appearance)
Test level: snapshot

## S1-AC20 — Accessibility and keyboard reachability of S1 controls
Given the main window
When VoiceOver inspects the drop zone, Choose Image, Export, Copy PNG, Clear, Undo and Redo controls
Then each has an accessibility label and (where relevant) a hint, e.g. "Export as PNG, ⇧⌘E"
And the canvas preview has the label "Preview, <W> by <H> pixels"
And every control can be reached and activated with Tab / Space without a mouse
Test level: app-smoke

## Open questions
- Exact default padding (64 px) and backdrop colour (#EDEDF2) are assumptions; confirm or change in `SunshotDefaults` (tests read from it).
- Should the preview scale-to-fit be capped at 100 % for small images (assumed yes: never upscale beyond 1:1 on a 1× display)?
- Multi-file drop imports only the first file for now; bulk import is S14.
- Whether HEIC/WebP decode is guaranteed on the minimum macOS 15 via ImageIO (assumed yes; AC2 fixtures will prove it).
- The final export file name template is S4; S1 uses the interim name in S1-AC10.
