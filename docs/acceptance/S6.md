# S6 — Position, tilt & layout presets — acceptance criteria

Conventions: content transform = `{x, y, zoom, rotation, tiltX, tiltY}`. `x,y` are normalised offsets of the content centre from the canvas centre, in canvas-width / canvas-height units, range −0.5…+0.5 (±0.5 = content centre on the canvas edge). `zoom` 25…400 % (default 100), `rotation` −180…180° (default 0), `tiltX`, `tiltY` −60…60° (default 0), perspective distance fixed at 4× the content's longer side. Default transform is identity. Snap threshold = 8 canvas px (preview-space), axis lock engages after 6 px of drag.

## S6-AC1 — Identity transform is the default and changes nothing
Given a new document
When the transform is read and rendered
Then it equals identity (x 0, y 0, zoom 100, rotation 0, tilt 0/0)
And the render is byte-identical to the pre-S6 snapshot of the same document
Test level: snapshot

## S6-AC2 — Position popover structure
Given content is loaded
When the Position control in the bottom toolbar is opened
Then tabs "Position" and "Tilt", a Zoom slider, a Rotation slider and a Reset button are present, with a mini canvas preview containing a draggable handle
And with no content loaded the control is disabled
Test level: app-smoke

## S6-AC3 — Dragging the position handle moves the content
Given the Position tab
When the handle is dragged from the centre to 25 % of the preview width to the right and 10 % of the height down
Then the model becomes x = +0.25, y = +0.10 (±0.005) and the main preview moves the content correspondingly
And the whole drag is one undo entry "Move Content"
Test level: unit

## S6-AC4 — Axis lock
Given a drag starting at the centre
When the pointer moves 40 px horizontally and 5 px vertically (dominant axis horizontal)
Then y stays 0 and x follows the pointer, and a guideline is drawn along the locked axis
And holding ⌥ disables the lock (free movement) and releasing the drag clears the guideline
Test level: unit

## S6-AC5 — Centre and edge snapping
Given a drag near a snap target
When the content centre comes within 8 px of the canvas centre line, or its edge within 8 px of the canvas edge
Then the position snaps exactly to the target (x = 0 / y = 0 or edge-flush) and a snap guide is shown
And holding ⌘ disables snapping
And positions beyond ±0.5 are clamped
Test level: unit

## S6-AC6 — Zoom
Given the Zoom slider
When set to 24, 25, 100, 400, 401 and typed 150.4
Then stored values are 25, 25, 100, 400, 400 and 150 (percent, integer, clamped)
And content scales about its own centre, 200 % doubles the content's pixel size in the render (±1 px), and the canvas size in Auto mode is not changed by zoom
Test level: unit

## S6-AC7 — 2D rotation
Given content 400×300 on a 1128×728 canvas
When rotation is 0°, 90°, −90°, 180°, 45° and typed 270
Then 90° and −90° swap the content's bounding extents (300×400) rotated about its centre, 180° keeps 400×300, 45° gives the 495×495 bounding box (±1 px), and 270 is normalised to −90
And values beyond ±180 are normalised into range, with no seams or lost pixels inside the content shape
Test level: unit

## S6-AC8 — Rotation keeps border, frame and shadow attached
Given a non-default border radius, frame = macWindow and shadow = spread/high
When rotation = 20°
Then the frame, rounded corners and shadow rotate together with the content as one object (shadow direction stays tied to the light source in canvas space, not rotated with the content)
And the output matches a snapshot
Test level: snapshot

## S6-AC9 — 3D tilt with perspective
Given the Tilt tab
When the handle is dragged to the right edge (tiltY = +30°) and then to the top edge (tiltX = +30°)
Then tilt values are stored within −60…60° and the content is rendered with perspective (near edge larger than far edge by the ratio implied by the 4× perspective distance, ±2 %)
And tilt 0/0 is exactly equal to a flat render
And a drag is one undo entry "Tilt Content"
Test level: snapshot

## S6-AC10 — Tilt preview/export parity
Given tilt (20°, −25°), rotation 10°, zoom 120 %, position (0.1, −0.05), frame, border and shadow
When the preview and the export (1×, 2×, 4K) are rendered
Then both come from the single render function and are byte-identical at each scale
And the 4K render is structurally equal to the 1× render (SSIM ≥ 0.98 after resizing) so perspective does not depend on scale
Test level: snapshot

## S6-AC11 — Extreme transforms stay safe
Given content 8000×8000, tilt 60°/60°, zoom 400 %, rotation 180°
When rendered at 1× and exported
Then no crash, no NaN/inf in the transform, and the canvas still renders (content is clipped to the canvas) in ≤ 2 s
And tiny content 1×1 at zoom 400 % renders 4×4 px without artefacts
Test level: unit

## S6-AC12 — Reset position
Given a customised transform
When the Reset (↺) button is pressed
Then all six values return to identity as one undo entry "Reset Position"
And pressing Reset when already identity adds no entry
And Reset does not change the active layout preset's thumbnail selection beyond clearing it
Test level: unit

## S6-AC13 — Layout preset catalogue
Given the left sidebar layout list
When it is displayed with content loaded
Then at least 12 Sunshot layout presets are listed from a bundled JSON file, each `{id, name, transform}` with unique ids, unique names, all values within the ranges above, and the first one equal to identity ("Centered")
And the catalogue contains at least: a flat centred layout, an offset-to-corner layout, a rotated layout, two different tilted layouts (left and right), and a layout where the content is partly cropped by the canvas edge
And the presets contain no names or pixel layouts copied from other products (review item recorded in the PR checklist)
Test level: unit

## S6-AC14 — Live thumbnails
Given content and the current style (backdrop, border, shadow, frame)
When the preset list is shown
Then each thumbnail is rendered by the same render function at thumbnail scale with the current content and style
And thumbnails regenerate within 300 ms after a style change (debounced) without blocking the main thread, and are cached by (document hash, preset id)
And with no content the list shows placeholder thumbnails and is disabled
Test level: integration

## S6-AC15 — Applying a preset
Given the layout list
When the user clicks a preset
Then the content transform becomes exactly the preset's transform, the preset gets an accent outline, and the change is one undo entry "Apply Layout <name>"
And manually changing any transform value afterwards removes the selection outline
And undo restores the previous transform and the previous selection state
Test level: unit

## S6-AC16 — Preset application is animated and honours Reduce Motion
Given a preset is applied
When Reduce Motion is off
Then the transition runs 300 ms (±50 ms) with ease-in-out and ends exactly at the target transform
And with Reduce Motion on the change is instantaneous
And an export started mid-animation always renders the final target transform, not an intermediate frame
Test level: integration

## S6-AC17 — Preset applies on top of every content shape and canvas
Given content 1000×600, 600×1000 and 100×100, canvases Auto, 1:1 and 9:16 (S4)
When each preset is applied
Then the content is never scaled to zero or positioned wholly outside the canvas (at least 20 % of the content area remains visible)
Test level: unit

## S6-AC18 — Keyboard control and accessibility
Given focus on the position handle, zoom and rotation sliders and the preset list
When used with the keyboard and VoiceOver
Then arrow keys move the handle by 0.01 (⇧: 0.05), sliders respond to arrows, the preset list is navigable with arrows and Return applies
And labels read "Content position, x 0.00 y 0.00", "Zoom, 100 percent", "Rotation, 0 degrees", "Layout: Centered, selected"
Test level: app-smoke

## S6-AC19 — Persistence and undo of every transform mutation
Given the document store
When position, tilt, zoom, rotation, reset and preset apply are each executed
Then each creates exactly one undo entry (drags coalesced), undo-all returns to identity, redo-all reproduces equal models, and the transform survives clear-content and re-import (kept as style) 
Test level: unit

## S6-AC20 — Render budget with tilt and thumbnails
Given tilt, rotation and frame enabled, a 3840×2160 canvas
When exported on Apple silicon (release build)
Then the median render time of 10 runs is ≤ 500 ms
And generating all preset thumbnails (≥ 12 at 200 px) completes in ≤ 600 ms in total off the main thread
Test level: integration

## S6-AC21 — Drag the screenshot on the canvas to move it
Given an image on the canvas
When the user presses on the screenshot in the main preview and drags it
Then the content follows the pointer with the same axis lock, centre / edge snapping and ⌥ / ⌘ modifiers as the
Position pad, guide lines are drawn over the preview, and the whole drag is one undo step "Move Content"
And pressing on the backdrop (outside the projected screenshot, frame chrome included) does not move the content
Test level: unit

## S6-AC22 — Pinch and twist on the canvas
Given an image on the canvas
When the user pinches on the preview
Then zoom = start zoom × magnification, whole percent, clamped to 25…400, one undo step "Change Zoom"
And when the user twists with two fingers, rotation = start rotation + angle, snapping to multiples of 45° within
4°, one undo step "Rotate Content"
Test level: unit

## S6-AC23 — Click the canvas to reach its controls
Given an image on the canvas
When the user clicks the backdrop
Then the inspector is shown and brings the Backdrop section into view, expanded
And clicking the screenshot brings the Border section into view, expanded; the request is repeatable
Test level: unit

## S6-AC24 — Preview fills the editor
Given a canvas smaller than the space available for the preview
When the preview is displayed
Then it is rendered at the displayed size (up to `previewMaxSide`) so it fills the area sharply instead of being
capped at one canvas pixel per screen pixel
Test level: unit

## S6-AC25 — Drag the backdrop to change the padding
Given an image on the canvas
When the user presses on the backdrop and drags away from the screenshot
Then the padding grows (toward it: shrinks) by the dragged distance in canvas pixels, whole pixels within
0…`maxPadding`, as one undo step "Change Padding"; a press without a drag stays a click (AC23)
Test level: unit

## S6-AC26 — ⇧-drag the screenshot to tilt it
Given an image on the canvas
When the user holds ⇧ and drags the screenshot
Then right leans the right side away (tiltY +), up leans the top away (tiltX +), 200 points reaching the Tilt pad's
edge tilt, whole degrees clamped to ±60°, one undo step "Tilt Content"
Test level: unit

## S6-AC27 — Corner radius handle
Given a flat, unrotated screenshot large enough on screen
When the pointer is over it
Then a handle is shown `radius` in from its top-left corner (at least 12 points), and dragging it diagonally sets
the radius (a sharp corner becomes smooth), one undo step "Change Corner Radius"
And the handle is hidden while the screenshot is rotated or tilted
Test level: unit

## S6-AC28 — Double-click to crop; drop on the backdrop; quick actions
Given an image on the canvas
When the user double-clicks the screenshot, Crop opens (double-clicking the backdrop does nothing)
And dropping one image on the backdrop makes it the backdrop image, while dropping on the screenshot replaces the
content as before
And right-clicking the canvas offers Shuffle Background, No Background, Reset Position, Crop… and Copy PNG
Test level: unit

## Open questions
- Normalised units for x/y and the 4× perspective distance are assumptions; Architect to confirm the transform model.
- Whether zoom in Auto-canvas mode should ever grow the canvas (assumed no: it is a pure content transform, clipping to the canvas).
- Group vs Single mode is out of scope until multi-item layouts (S12).
- Drag-reorderable preset list (reference mentions keyboard drag) is not included.
- Preset names and exact transforms are for the Designer to specify; AC13 constrains only variety and ranges.
