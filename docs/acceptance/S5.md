# S5 — Frames & colour tokens — acceptance criteria

Conventions: frame kinds = `none | macWindow | browserWindow | card | stack | stack2 | thickBorder | winWindow`. Every frame is vector-drawn by Sunshot (no bitmap chrome assets). Frame model = `{kind, title: String, uiScale: 50…200 %}`; defaults: kind none, title "", uiScale 100 %. Colour tokens = `foreground, background, secondary, primary` (sRGB); fonts = `text`, `code`. Chrome appearance = `light | dark | auto` (auto follows the Foreground/Background luminance of the tokens, not the system). Bundled fonts are open-licence only (SIL OFL / Apache) with licence files shipped.

## S5-AC1 — Frame picker lists all eight frames
Given a document with content
When the Frame control is opened
Then it shows exactly eight options in this order: None, Mac window, Browser window, Card, Stack, Stack 2, Thick border, Windows window, each with a live thumbnail rendered by the same frame renderer
And the current frame is marked selected, and selecting another is one undo entry "Change Frame"
Test level: unit

## S5-AC2 — Frame none is the default and changes nothing
Given a new document
When the render is compared with the S2 default snapshot
Then it is byte-identical (frame none adds no pixels, padding or layout shift)
Test level: snapshot

## S5-AC3 — Mac window frame
Given frame = macWindow and content 800×500
When rendered
Then a title bar of 28 px × uiScale is drawn above the content with three traffic-light circles (12 px diameter, 8 px gap, 12 px from the left) in the standard red/yellow/green hues
And the title text is centred in the bar, truncated with "…" when wider than the available space
And the window silhouette (bar + content) shares the corner radius and shadow from S2
And the output matches snapshots in light and dark chrome
Test level: snapshot

## S5-AC4 — Browser window frame
Given frame = browserWindow
When rendered
Then a toolbar of 44 px × uiScale is drawn with three window controls, back/forward glyphs and a rounded address field containing the title (or a placeholder "example.com" when title is empty)
And all glyphs are Sunshot-drawn vector shapes
And the output matches light and dark snapshots
Test level: snapshot

## S5-AC5 — Windows-style window frame
Given frame = winWindow
When rendered
Then a title bar of 32 px × uiScale is drawn with the title left-aligned and minimise / maximise / close glyphs right-aligned
And the output matches light and dark snapshots
Test level: snapshot

## S5-AC6 — Card, stack and stack 2
Given frames card, stack and stack 2 on content 800×500
When rendered
Then card draws the content on a rounded card with 24 px × uiScale inner padding in the Background token colour
And stack draws one extra card behind, offset 12 px up and scaled 96 %, and stack 2 two cards (offsets 12 and 24 px, scales 96 % and 92 %) with decreasing opacity
And none of the extra cards extends outside the canvas for Auto size
And snapshots match
Test level: snapshot

## S5-AC7 — Thick border frame
Given frame = thickBorder
When rendered
Then a rounded border of 14 px × uiScale in the Secondary token colour surrounds the content, following the corner radius of S2 (outer radius = radius + border width)
And snapshots match in light and dark
Test level: snapshot

## S5-AC8 — Frame grows the Auto canvas, never covers content
Given Auto canvas, content 1000×600, frame macWindow at uiScale 100 %
When canvas size is computed
Then the canvas is 1128×756 px (content + 28 px bar + 64 px padding all round)
And the content pixels remain unscaled and fully visible, and the same rule holds for every other frame kind with its own chrome size
Test level: unit

## S5-AC9 — Inline title edit
Given a frame with a title bar (mac, browser or Windows)
When the user double-clicks the title (or presses Return with the title focused) and types "Release notes"
Then the title updates live in the preview, Return commits, Esc cancels and restores the previous title
And a title is limited to 120 characters (longer input is truncated), may contain emoji and right-to-left text, and is not clipped outside the bar
And the committed edit is one undo entry "Edit Frame Title"
Test level: app-smoke

## S5-AC10 — Title edit model rules
Given the frame title model
When the title is set to "", "   ", a 500-character string, and a string with newline characters
Then empty/whitespace titles render as empty (placeholder shown only in the editor), the long string is cut to 120 characters, and newlines are replaced with spaces
Test level: unit

## S5-AC11 — UI scale
Given a frame with chrome and the UI scale control
When the value is set to 49, 50, 100, 200, 201 and 150.5
Then stored values are 50, 50, 100, 200, 200 and 151 (percent, rounded, clamped)
And chrome dimensions, glyph sizes and title font size scale linearly with it while the content is not scaled
And a drag of the slider is one undo entry
Test level: unit

## S5-AC12 — Colour tokens model and defaults
Given a new document
When the four tokens are read
Then foreground = #1D1D1F, background = #FFFFFF, secondary = #6E6E73, primary = #0A84FF (defaults, constants in `SunshotDefaults`)
And each token can be changed via a colour well or HEX input with the same validation as S3-AC5
And every change is one undo entry, and "Reset Colors" restores all four (no-op without an entry if already default)
Test level: unit

## S5-AC13 — Tokens drive frame chrome
Given frame = macWindow with foreground #FF00FF, background #00FF00
When rendered
Then the title text uses the foreground colour and the title bar fill uses the background colour (sampled within ±1/channel)
And changing a token never alters the backdrop or content pixels
Test level: snapshot

## S5-AC14 — Light/dark chrome
Given the chrome appearance is set to light, dark and auto
When rendered with a dark Background token (#101014) and a light one (#FFFFFF)
Then light and dark force their respective chrome palettes regardless of tokens
And auto picks dark chrome when the Background luminance < 0.5 and light chrome otherwise
And the title text always meets contrast ≥ 4.5:1 against the title bar in the six combinations
Test level: unit

## S5-AC15 — Fonts
Given the Fonts section
When the Text and Code font pickers are opened
Then each lists the bundled open-licence fonts first (≥ 2 text families and ≥ 1 monospaced family) followed by installed system fonts
And selecting a font changes the frame title font immediately (Text) and is stored by PostScript name
And a font that is missing at load time falls back to the system font without crashing and shows "Font unavailable" in the picker
And a `LICENSES/` folder in the bundle contains a licence file for every bundled font (repository check)
Test level: unit

## S5-AC16 — Frame, token and font changes are undoable and persisted
Given the document store
When frame kind, title, UI scale, each token, fonts, chrome appearance and the colour/font resets are changed
Then every action is exactly one undo entry with a descriptive name and undo-all/redo-all reproduces equal models and byte-identical renders
Test level: unit

## S5-AC17 — Frame interaction with transparent content and large images
Given a transparent PNG with frame = card, and an 8000×8000 image with frame = macWindow, uiScale 100 %
When rendered and exported at 1×
Then the transparent region shows the card colour behind the content only for card/stack frames (chrome frames show the window body colour) and never the backdrop
And the large export is 8128×8156 px, completes with peak memory growth ≤ 1.5 GB
Test level: integration

## S5-AC18 — Preview/export parity and render budget with frames
Given frame = browserWindow, shadow high, gradient backdrop
When rendered at 1×, 2× and 4K (3840-px long edge)
Then preview and export outputs are byte-identical at each scale
And the 4K render completes in ≤ 500 ms median on Apple silicon
Test level: integration

## S5-AC19 — Frames are vector-sharp at export scale
Given frame = macWindow rendered at 1× and 4K
When the title-bar edge region is compared
Then the 4K render has crisp edges (no resampling blur: edge transition ≤ 2 px wide) rather than an upscaled 1× bitmap
Test level: snapshot

## S5-AC20 — Accessibility of frame and colour controls
Given the Frame picker, title field, UI scale slider, colour wells and font pickers
When used with VoiceOver and keyboard only
Then each frame option has a label ("Frame: Mac window, selected"), the slider announces "UI scale, 100 percent", colour wells announce token name and hex value, and all are reachable by Tab
And the frame preview in the canvas exposes the title as an accessibility value
Test level: app-smoke

## Open questions
- Chrome dimensions (28/44/32/14 px) and stack offsets are design placeholders; the UI/UX Designer should confirm so snapshots can be baselined.
- Token defaults are assumptions; "auto" chrome rule is defined here by luminance threshold 0.5.
- Which open-licence font families to bundle (candidate: Inter-like sans and a monospace family under OFL) needs an Architect/Designer decision; AC15 only fixes counts and licence-file presence.
- Whether frame title also appears in exported metadata (assumed no).
