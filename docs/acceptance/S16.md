# S16 — Menu bar quick capture, default style & studio journey — acceptance criteria

Sunshot keeps running in the menu bar so the capture shortcut always works. A shortcut capture is copied to the
clipboard already styled with the user's **default style** (a whole `Project` minus per-image parts: annotations,
animation, screenshot layout), saved from the studio with **Save as Default Style**. New documents start from the
default style, and captures opened in the studio start in Annotate mode. Capture Window picks windows by hovering
them on screen, like the system screenshot. A document shows either its screenshot or its code snippet; the
toolbar's **Screenshot | Code** switch moves between them and keeps the other side.

## S16-AC1 — Defaults and settings
Given a fresh install
Then the global shortcut (⌥⇧⌘4) is on and copies with the default style, the menu bar icon is shown and captures
opened in the studio start in Annotate mode; each can be changed in Settings ▸ Menu bar & quick capture and the
choices are saved
Test level: unit

## S16-AC2 — Styled clipboard capture
Given Settings ▸ After a shortcut capture is "Copy with default style"
When an area or a window is captured with the shortcut or from the menu bar
Then the clipboard holds a PNG of the capture rendered with the default style (the default template's style when
none is saved) through the one `Renderer.render`, at one canvas pixel per captured pixel; the open document is
unchanged, and a capture that fails or is not permitted copies nothing
Test level: unit

## S16-AC3 — Save as Default Style
Given a document in the studio
When Save as Default Style is chosen (Export button menu)
Then its style and layout are saved (without annotations, animation or screenshot layout) and used for quick
captures, File ▸ New, Start Over and launch; they survive relaunch; Settings shows when it was saved and Clear
forgets it; an unreadable or newer-version file is ignored
Test level: unit

## S16-AC4 — Hover to pick a window
Given Capture Window (menu bar, toolbar, File menu)
Then every screen gets a clear overlay; the front-most window under the pointer is tinted and outlined with its
app, title and size; a click captures it, a click on the desktop or Esc cancels, Space switches to area capture
(and Space in area capture switches back); Sunshot's own windows, windows without a frame and tiny helper windows
are not offered
Test level: unit

## S16-AC5 — The studio opens in Annotate mode
Given "Open captures in Annotate mode" is on
When a capture is opened in the studio (shortcut set to Open in Sunshot, Capture … into Studio, File ▸ Capture …)
or the studio is opened from the menu bar with content
Then Annotate mode is on (when the content can be annotated)
Test level: unit

## S16-AC6 — Screenshot ⇄ Code
Given a document with a screenshot
When the toolbar switch goes to Code, then back to Screenshot
Then the code snippet shows (an empty one the first time) and the screenshot comes back with its crop and
annotations, and the snippet is kept for the next switch; each switch is one undo step; New Code Snippet keeps the
screenshot too; Screenshot with no image shows the empty "drop an image" state
Test level: unit

## S16-AC7 — In the running app
Given the running app
Then the menu bar icon shows the menu (captures, Open Studio, default-style status, Settings, Hide Menu Bar Icon,
Quit); closing the studio window keeps Sunshot running in the menu bar without a Dock icon and the shortcut still
copies styled captures with a "copied" bubble; Open Studio brings the window back; hiding the icon while the
window is closed brings the studio forward; the hover picker highlights windows on every display in Light and Dark
Test level: manual
