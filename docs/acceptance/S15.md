# S15 — Multiple screenshots — acceptance criteria

Conventions: a document still has one **main** image (`EditorDocument.content`, the one the canvas lays out, crops,
annotates and animates) plus optional **slot images** (`EditorDocument.slots`, keyed by screenshot number: 1, 2…
for the non-primary slots in arrangement order, so images keep their order when a layout grows). Slots come
from the active arrangement: the device arrangement (S12: Pair, Trio, fixed combinations) when a device is set,
otherwise the **screenshot layout** (`Project.collage`, an id into `CollageCatalog`; nil = one screenshot). The
primary slot always shows the main image; any other slot shows its own image, or the main image while it has
none — so every existing document and template renders exactly as before. In a **screenshot layout** every
screenshot is shown **whole, never cropped**: at its own aspect, with the main screenshot's content height (so the
frame chrome matches), scaled down to fit its slot and centred. **Device screens** have a fixed shape, so there the
image is aspect-filled (centre-cropped) like S12.

Screenshot layouts are Sunshot's own arrangements of 2–4 copies of the S5 frame silhouette (frame chrome, corners,
content). Slot geometry is data in `CollageCatalog`: centre and height relative to the primary frame box, a 2D
rotation, back-to-front order, exactly one primary slot with centre (0.5, 0.5), height 1 and no rotation. The
primary frame box is laid out exactly as without a layout; the other slots are frame insets around it, so a layout
grows an Auto canvas the way S5 chrome does. The whole layout is one silhouette inside the S6 transform and the S2
shadow layer, through the single `Renderer.render`. A device and a screenshot layout are mutually exclusive.

## S15-AC1 — Screenshot layout catalog is valid
Given the bundled `CollageCatalog`
When it is loaded
Then every layout has a unique id and name, 2–4 slots, exactly one primary slot at centre (0.5, 0.5) with height
1 and rotation 0, every slot height is in 0.3…1.2 and every rotation within ±30°, and unknown ids resolve to no
layout
Test level: unit

## S15-AC2 — Layout geometry grows the canvas around the primary frame box
Given a primary frame box of W×H and a screenshot layout
When the layout is computed
Then each slot's box keeps the primary box's aspect, scaled by the slot height, centred at its centre; the
bounding box contains every rotated slot exactly (tight), the primary slot is placed at the same size, and the
frame insets are the bounding box minus the primary box, so `CanvasLayout` keeps content pixels 1:1
Test level: unit

## S15-AC3 — Each device of an arrangement can show its own image
Given a Pair, Trio or fixed-combination device arrangement and an image set for a non-primary slot
When rendered
Then that slot's screen shows the slot image aspect-filled, the primary screen still shows the main image, and
slots without an image show the main image (the S12 output is unchanged when no slot image is set)
Test level: snapshot

## S15-AC4 — Screenshot layouts render each slot with the frame chrome
Given a screenshot layout, a window frame and slot images for some slots
When rendered
Then every slot draws the frame silhouette (chrome, corners, title) around its own image (or the main image),
shown whole at its own aspect and fitted into the slot (never cropped), back to front with its rotation, the shadow follows the whole layout's outline, annotations draw on the primary
slot only, and the output matches snapshots
Test level: snapshot

## S15-AC5 — Slot edits are undoable
Given a document with content
When the user sets or removes a slot image, or changes the screenshot layout
Then each is one named undo step ("Set Screenshot", "Remove Screenshot", "Change Screenshot Layout"), edits
that change nothing record nothing, the primary slot can't be given a slot image, and Clear Content also clears
slot images (undo restores them)
Test level: unit

## S15-AC6 — Device and screenshot layout are mutually exclusive
Given a screenshot layout
When the user chooses a device, the layout is removed (and choosing a screenshot layout removes the device), in
one undo step each; slot images are kept so switching back shows them again
Test level: unit

## S15-AC7 — Slot images are saved in the document
Given a document with slot images
When it is saved as a `.sunshot` package and reopened
Then each slot image's original bytes are in `media/`, `document.json` lists them under `slots`
(`{number, mediaID, pixelSize}`), reopening restores the same slots, a missing slot file follows the S7
placeholder rules, and documents without `slots` open unchanged
Test level: integration

## S15-AC8 — Preview and export parity
Given a document with a screenshot layout or a multi-device arrangement and slot images
When the preview and a 1× export are rendered
Then they are pixel-identical (one render path)
Test level: snapshot

## S15-AC9 — Screenshots inspector
Given content and a screenshot layout or a multi-device arrangement
Then the inspector's Screenshots section lists one row per slot (Main first) with a thumbnail; a row can choose
an image (open panel or drop), and a non-main row with an image can remove it; the section's layout picker
offers None plus every screenshot layout and is disabled while a device is set
Test level: manual

## S15-AC10 — Paste and capture add the next screenshot
Given image content is open (not a code snippet or a video)
When the user pastes an image (⌘V) or captures the screen or a website
Then the image fills the first empty screenshot (by number) in one undo step "Add Screenshot", and when every
slot is filled the layout grows first: one screenshot → Side by Side → Row of Three → Grid (Overlap → Cascade →
Grid, Fan → Grid); a device grows Single → Pair → Trio and keeps its model
And a notice says where it went ("Added as screenshot 2 · Side by Side"); when nothing holds one more, nothing
changes and the notice says all screenshots are filled
And with no content (or a snippet or video) the image becomes the content as before; Open and drop still replace
the main image
Test level: unit

## S15-AC11 — Any screenshot can be removed
Given a document with two or more screenshots
When the user removes one (Remove on its row; the main one too)
Then it is one undo step "Remove Screenshot": the later screenshots move up one place (removing the main one makes
the next screenshot the main image and drops the crop), and the layout shrinks to fit (Grid → Row of Three →
Side by Side → one screenshot; Cascade → Overlap; Fan → Side by Side; a device → the largest plain arrangement
that fits); the last remaining image can only be cleared with Clear Content
Test level: unit

## S15-AC12 — Drag and drop swaps screenshots
Given a document with screenshots in a layout
When the user drags a row of the Screenshots list onto another row
Then the two screenshots swap places in one undo step "Move Screenshot" (the crop is dropped when the main
image changes); the main slot can never be left empty, and dropping an image file on a row fills that screenshot
Test level: unit

## S15-AC13 — Adding a screenshot resets a preset that runs off the canvas
Given a layout preset or transform that runs off the canvas (zoom over 100 %, or an offset over 0.15 of the
canvas — Close-up, Bleed Right, Corner Peek, Rise from Below)
When a paste or capture adds a screenshot
Then the placement is reset to centred in the same "Add Screenshot" undo step, so no screenshot is cut off;
presets that stay on the canvas (tilts, rotations, drifts, Breathing Room) are kept
Test level: unit

## S15-AC14 — Pasted and captured screenshots lose a solid border
Given a pasted image or a screen capture whose four corners are the same opaque colour (a copied canvas backdrop,
a desktop strip around an area capture)
When it is added (as the main image or a further screenshot)
Then the rows and columns of that colour (within 10 per channel, ≥ 99.5 % of the line) are cut off every side, the
trimmed image is stored as PNG, and the notice says the border was trimmed
And transparent margins (window captures), borders under 3 px, results under 20 % of a side, website captures and
images opened or dropped from files are left unchanged
Test level: unit

## Open questions
- Dragging screenshots directly on the canvas (needs hit-testing through the S6 transform) — deferred; reorder
  happens in the Screenshots list.
- Per-slot crop and annotations — deferred; they stay on the main image.
- Bulk edit (S14) and video export keep the main image's behaviour; slot images ride along unchanged.
