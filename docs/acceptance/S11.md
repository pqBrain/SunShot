# S11 — Code snippet template — acceptance criteria

Conventions: a document's content is either an image or a code snippet, never both. Snippet model = `{code, language (nil = auto-detect), showLineNumbers, highlightedLines (1-based line numbers), title, theme (id), fontSize, padding, fontName (PostScript name, nil = default monospaced)}`; defaults: a short Sunshot starter snippet, language auto, line numbers on, no highlighted lines, title "", theme `daybreak` (light), font size 15 px (8…48), padding 28 px (0…120), font Menlo. Starter languages: Swift, JavaScript, TypeScript, Python, JSON, HTML/XML, CSS, Shell, Go, Rust, SQL, Plain text. Token kinds: plain, keyword, type, string, number, comment, function, property, tag, attribute, variable, punctuation. Code is normalised before measuring and highlighting: CRLF / CR → LF, tab → 4 spaces. Sizes are canvas pixels at 1×.

## S11-AC1 — New Code Snippet creates a snippet document
Given an empty document, or a document with an image
When "New Code Snippet" is chosen (File menu ⌥⌘N, or the empty-state button)
Then the document content becomes a snippet with the default values, the image (if any) is removed, and this is one undo entry "New Code Snippet"
And Undo restores the previous content exactly (image or empty)
Test level: unit

## S11-AC2 — Snippet defaults and clamping
Given a new snippet
Then its fields equal the defaults in Conventions
And font size is clamped to 8…48 and padding to 0…120; non-finite values fall back to the default
And highlighted lines below 1 are dropped
Test level: unit

## S11-AC3 — Snippet is Codable with tolerant decoding
Given a snippet with every field set to a non-default value
When it is encoded to JSON and decoded
Then the result equals the original
And decoding JSON with missing keys yields the defaults for those keys, an unknown language becomes auto-detect, an unknown theme id falls back to the default theme on render, and unknown keys are ignored
Test level: unit

## S11-AC4 — Highlighter classifies each starter language
Given a fixture for each of the eleven starter languages (plus plain text)
When it is tokenised
Then keywords, types, strings, numbers, comments (and tags/attributes for HTML/XML, properties for JSON/CSS, variables for Shell) get the expected kinds
And plain text yields no coloured tokens
Test level: unit

## S11-AC5 — Highlighter is total and robust
Given any input, including empty text, unterminated strings and block comments, emoji and CJK, CRLF line endings and very long lines
When it is tokenised
Then tokens are sorted, never overlap, never split a UTF-16 surrogate pair and lie within the text
And the call never crashes or hangs (an unterminated string or comment runs to the end of its line or the text)
Test level: unit

## S11-AC6 — Language auto-detect
Given the language is auto
When the code is a recognisable sample of a starter language
Then the detected language is that language (fixture per language)
And short or ambiguous text detects as Plain text
And choosing a language explicitly overrides detection
Test level: unit

## S11-AC7 — Sunshot code themes are data
Given the code theme catalog
Then it holds at least four Sunshot-named themes, at least two light and two dark, with unique ids
And every theme defines a colour for every token kind plus background, text, line numbers, highlighted-line band and title
And plain text on the background has contrast ≥ 4.5:1 and every token colour ≥ 3:1; line numbers ≥ 2.5:1
Test level: unit

## S11-AC8 — Snippet content size
Given a snippet
When its content size is measured
Then width = padding + gutter + longest line + padding (with a minimum text width of 24 columns) and height = padding + title row + lines × line height + padding, rounded up to whole pixels
And line height = round(fontSize × 1.5); an empty snippet still has one line; a trailing newline adds an empty line
Test level: unit

## S11-AC9 — Snippet renders with its theme
Given the default snippet in the default light theme, and the same snippet in a dark theme with line numbers off
When rendered
Then the output matches the reference snapshots, the background is the theme background, and text pixels use the theme's token colours
Test level: snapshot

## S11-AC10 — Line numbers toggle
Given a snippet of 12 lines
When line numbers are on
Then a gutter wide enough for the widest number ("12", at least 2 digits) is drawn left of the code with right-aligned numbers in the line-number colour
And when line numbers are off there is no gutter and the content is narrower by exactly the gutter width
Test level: unit

## S11-AC11 — Highlighted lines
Given the highlighted-lines field
When "2, 4-6" is entered
Then lines {2, 4, 5, 6} are highlighted with a full-width band in the theme's highlight colour behind the text
And invalid text ("abc", "0", "6-4") is rejected without changing anything, an empty field clears the set, and line numbers beyond the last line are ignored when drawing
And the set formats back as "2, 4–6"
Test level: unit

## S11-AC12 — Optional title row
Given an empty title, no title row is drawn and no height is added
When a title is entered
Then a title row (height round(fontSize × 2.4)) is drawn above the code with the title centred in the title colour, truncated with "…" when wider than the content
Test level: snapshot

## S11-AC13 — Snippet flows through the normal pipeline
Given a snippet document with a gradient backdrop, padding, round corners, a shadow and a ratio canvas
When it is rendered
Then the output equals rendering the snippet's own content image through the image pipeline with the same style (backdrop, padding, border, shadow, canvas size all apply; one render function)
Test level: unit

## S11-AC14 — Export re-renders code at export scale
Given a snippet document exported at 2× (and an exact canvas that scales the content up)
When rendered
Then the code is drawn at the output pixel density (not an upscaled 1× bitmap): the output equals the pipeline fed with the snippet rendered at that density, and differs from the result of upscaling the 1× snippet
Test level: unit

## S11-AC15 — Snippet edits are undoable named steps
Given a snippet document
When the language, theme, line numbers, highlighted lines, title, font size or padding is changed
Then each change is one undo entry ("Change Language", "Change Code Theme", "Toggle Line Numbers", "Change Highlighted Lines", "Change Snippet Title", "Change Code Font Size", "Change Code Padding"), Undo restores the old value, and a change to the current value records nothing
And Reset (Code section) restores theme, line numbers, font size, padding and font to their defaults but keeps the code, language, title and highlighted lines, as one entry "Reset Code Style"
Test level: unit

## S11-AC16 — Typing is coalesced into undo entries
Given the code editor
When several keystrokes arrive less than 1 s apart
Then they form one undo entry "Typing"; the entry closes after 1 s without typing, or as soon as another edit, Undo or Redo happens
And Undo after a typing run restores the text from before the run
Test level: unit

## S11-AC17 — Image and snippet content replace each other
Given a snippet document
When an image is imported or pasted, the image replaces the snippet ("Replace Image"); Clear Content removes the snippet
And for a snippet document Copy, Export and the inspector are enabled, the canvas size reflects the snippet size, and the export file name uses the template name "code"
Test level: unit

## S11-AC18 — Code editor panel and Code inspector section
Given a snippet document
When the window is shown
Then a code editor panel (monospaced, placeholder "Enter some code…", no smart quotes or autocorrect) sits below the preview and edits update the preview live
And the inspector shows a Code section with Language (Auto-detect + starter languages, showing the detected one), Theme, Line numbers, Highlighted lines, Title, Font size and Padding, each with a VoiceOver label
And image documents show neither the editor nor the Code section
Test level: app-smoke

## S11-AC19 — Snippet render performance
Given a 500-line snippet (Swift, line numbers on, title, 5 highlighted lines)
When it is highlighted, measured and rendered at 1× (release build)
Then highlighting + 1× render takes ≤ 150 ms (median of 5)
And a 300-line snippet (the largest that stays within the 16384 px export limit at 2× with default settings) renders at 2× in ≤ 400 ms
Test level: unit
