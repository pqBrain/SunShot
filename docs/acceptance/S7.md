# S7 — Documents, themes, settings & menus — acceptance criteria

Conventions: a `.sunshot` document is a package directory (UTI `app.sunshot.document`, conforming to `com.apple.package`) containing `document.json` (schema-versioned, `schemaVersion` integer starting at 1), a `media/` folder with original content/backdrop images, and optional `thumbnail.png`. A theme = the style subset of the model (backdrop, border, shadow, frame, colour tokens, fonts) without content, canvas size or transform. Settings are stored in `UserDefaults` under the `app.sunshot.` prefix. Defaults: appearance = system, confirm-reset = on, default export folder = none (ask each time), filename template = `{TEMPLATE}_{SCALE}_sunshot_{DATE}`, default template = "Screenshot".

## S7-AC1 — Save and reopen round-trip
Given a document with content, non-default backdrop, border, shadow, frame, tokens, fonts, canvas size, export options and transform
When it is saved as `Test.sunshot` (⌘S saves the document, ⇧⌘E exports the image; see Open questions) and reopened
Then the loaded model is equal (Equatable) to the saved model and the render is byte-identical to the render before saving
And the package contains `document.json`, the original media bytes unchanged (SHA-256 equal) and a schema version
Test level: integration

## S7-AC2 — Document JSON schema stability
Given the checked-in golden file `fixtures/v1/document.json`
When it is decoded by the current app version
Then decoding succeeds and the result equals the expected model
And unknown extra keys are ignored, missing optional keys take defaults
And a file with `schemaVersion` greater than the app's version opens read-only with the message "This document was made with a newer version of Sunshot"
And any `schemaVersion` migration has a fixture and test
Test level: unit

## S7-AC3 — Corrupt or hostile documents
Given packages with missing `document.json`, invalid JSON, a media reference to a missing file, a media file of 0 bytes, and a path-traversal reference (`../../x`)
When each is opened
Then the app never crashes, shows "Can't open this document" with a reason, and for the missing-media case offers to open with the placeholder
And the traversal reference is rejected and nothing outside the package is read
Test level: unit

## S7-AC4 — Autosave
Given a document that has been saved once (or an untitled one)
When the model changes and 5 seconds elapse without further change (or the app resigns active / terminates)
Then the changes are written (saved documents in place; untitled documents to `~/Library/Application Support/Sunshot/Drafts/<uuid>.sunshot`)
And the write is atomic (temp file + rename) so an interrupted write never corrupts the previous version
And autosave happens off the main thread and a 20-MB-media document does not stall typing or dragging
Test level: integration

## S7-AC5 — Crash/quit recovery of untitled work
Given an untitled document with unsaved changes and a force-quit
When the app is launched again
Then the untitled draft is restored with its content and style, and appears in the window as "Untitled"
And a successfully closed untitled document with no content leaves no draft behind
Test level: integration

## S7-AC6 — Open Recent
Given the user has opened or saved 12 different documents
When File ▸ Open Recent is opened
Then at most 10 items are listed, most recent first, each by name, with "Clear Menu" at the bottom
And a recent item whose file was deleted is greyed or removed and shows an alert "File not found" when chosen
And "Clear Menu" empties the list
Test level: integration

## S7-AC7 — Start Over with confirmation
Given a document with content and the setting "Confirm before resetting" on
When the user chooses File ▸ Start Over (or the toolbar broom button)
Then a confirmation dialog "Start over?" with buttons "Start Over" (destructive) and "Cancel" appears and Cancel changes nothing
And confirming resets content and all style to defaults and is one undo entry "Start Over", and Undo restores everything byte-for-byte
Test level: app-smoke

## S7-AC8 — Start Over without confirmation and in empty state
Given "Confirm before resetting" is off
When Start Over is invoked with content, then again with an already default document
Then the first resets immediately without a dialog (undoable) and the second is a no-op that adds no undo entry (menu item disabled)
Test level: unit

S7-AC9 (Save theme), S7-AC10 (Apply theme) and S7-AC11 (Theme management) were retired by S17-AC1: the theme
library is gone and the default style (Set as Default) is the one saved style. Documents saved with a theme still
open with their style.

## S7-AC12 — Settings window
Given Sunshot ▸ Settings… (⌘,)
When the window is opened
Then it shows Appearance (System / Light / Dark), Filename format (text field with live preview and Reset), Default export folder (path with Choose… and Clear), "Confirm before resetting" toggle, and Default template (Screenshot only for now, disabled picker)
And values persist across relaunch and the window title bar is "Settings"
Test level: app-smoke

## S7-AC13 — Appearance setting
Given appearance = Light, Dark, then System
When each is selected
Then the app's windows and popovers switch immediately via the app-wide appearance override (System follows the OS) and exported images are unaffected
And the choice persists across launches
Test level: integration

## S7-AC14 — Filename format setting and preview
Given the filename field
When the template is edited to `{TEMPLATE}-{WIDTH}x{HEIGHT}`, an invalid one (empty), and Reset is pressed
Then the live preview shows the example result using the S4 rules (e.g. `screenshot-1128x728.png`), an empty template shows the warning "Using the default format" and Reset restores `{TEMPLATE}_{SCALE}_sunshot_{DATE}`
And the saved export name (S4) uses the setting for every new export
Test level: unit

## S7-AC15 — Default export folder
Given a default export folder is set to `~/Pictures/Sunshot`
When the user exports with ⇧⌘E
Then the file is written there directly without a save panel, and a name collision appends ` 2`, ` 3`… rather than overwriting
And if the folder is missing or not writable, the save panel opens at the Pictures folder instead with a one-line notice
And clearing the setting restores the save panel on every export
Test level: integration

## S7-AC16 — Settings are used by new documents and survive Start Over
Given non-default settings
When Start Over is run or a new document is created
Then the settings (not document state) are unchanged, and the default template (Screenshot) is applied
Test level: unit

## S7-AC17 — Menu bar mirrors every shortcut
Given the running app
When the menu bar is inspected
Then these items exist with their shortcuts and enabled states: File ▸ New (⌘N), Open… (⌘O), Open Recent, Close (⌘W), Save (⌘S), Save As… (⌥⇧⌘S), Export Image… (⇧⌘E), Start Over; Edit ▸ Undo (⌘Z), Redo (⇧⌘Z), Cut/Copy (⌘C copies the PNG)/Paste (⌘V)/Select All system items, Clear Content; View ▸ Show/Hide Inspector (⌘⌥E), Enter Full Screen; Window ▸ Minimize, Zoom; Help
And every keyboard shortcut defined in S1–S6 is listed in at least one menu
And no two menu items share a key equivalent (checked from the menu definition)
Test level: unit

## S7-AC18 — Menu enablement follows state
Given an empty document, then a document with content, then after a save
When menus are validated
Then Export Image, Copy, Clear Content, Start Over and Save are disabled in the empty state, enabled with content, and Save As / Open Recent work in all states
And Undo/Redo titles show the action name ("Undo Change Corner Style")
Test level: app-smoke

## S7-AC19 — Dirty state and close behaviour
Given a document with unsaved changes
When the window is closed (⌘W) or the app quit (⌘Q)
Then with autosave the document closes without prompting after a final save, and a document never saved prompts "Save changes to Untitled?" with Save / Don't Save / Cancel only if it has content
And Cancel keeps the window open and the state intact
Test level: app-smoke

## S7-AC20 — Preview/export parity after reload; 4K budget
Given a saved and reloaded document with all features from S1–S6 enabled
When rendered and exported at 1×, 2× and 4K
Then outputs are byte-identical to the pre-save outputs, and the 4K export completes in ≤ 500 ms median on Apple silicon (excluding I/O and document load)
Test level: integration

## S7-AC21 — Large document save/load
Given a document holding an 8000×8000 content image and an 8000×8000 image backdrop
When it is saved and reopened
Then save and load each complete in ≤ 3 s on Apple silicon with peak memory growth ≤ 1.5 GB, media are stored once (not duplicated in JSON) and the package size is ≤ 1.1× the sum of the media file sizes
Test level: integration

## S7-AC22 — Accessibility of settings and document UI
(S17-AC1 removed the theme header and menu.)
Given the Settings window and dialogs
When used with VoiceOver and keyboard only
Then every field and button has a label, dialogs focus their default button and respond to Return/Esc, and Settings tabs are reachable by Tab
And all screens are legible in Light and Dark appearance (contrast ≥ 4.5:1 for text)
Test level: app-smoke

## S7-AC23 — A short toolbar; nothing lost
Given the editor window
When its toolbar is shown
Then it holds only Add Image, Capture, Annotate, Animate, Export and the inspector toggle (Clear, Start Over, Copy PNG, Templates and the separate export-options button are gone)
And a click on Export exports as before, while Export's menu offers Copy PNG (same as ⌘C) and Export Options… (the format and size popover); when the options make export impossible a click opens them
And Clear Content (⌘⌫), Start Over (File menu), Copy (⌘C) and Templates… (⇧⌘T) stay reachable from the menu bar with the same enablement
Test level: unit (menu catalog + enablement), manual (toolbar)

## S7-AC24 — One picker for layouts, templates and themes
(S17-AC1 removed the Themes pane: the default style is the one saved style. The rest stands.)
Given the left sidebar
When the picker at its top is switched between Layouts, Templates and Themes
Then Layouts lists the layout presets (before an image is added only the hint "Add an image to try layouts." is shown, no placeholder tiles), Templates lists the templates previewed with the current content plus "Show all templates…" (the gallery sheet), and Themes shows the applied theme, the saved themes (click applies, right-click renames, duplicates or deletes) and "Save current style as theme"
And the inspector no longer starts with a theme menu; each choice is one undo step as before
Test level: unit (pane order and copy), manual (sidebar)

## S7-AC25 — Automatic backdrop for the first image
Given "Style the backdrop from the first image" on in Settings (the default) and a document whose backdrop is still the new-document default (colour and effects)
When the first image is added (open, drop, paste or capture)
Then the backdrop becomes the first auto background made from the image's colours, in the same "Import Image" undo step (one Undo returns to the empty default document)
And nothing changes when the setting is off, when the backdrop or its effects were changed first, when an image is replaced, or when an image follows Clear Content; the setting persists across relaunch
Test level: unit

## Open questions
- Keyboard shortcut conflict: S1 assigns ⌘S to export-PNG, while a document-based app normally uses ⌘S for Save. This file assumes ⌘S = Save document and ⇧⌘E = Export Image from S7 onward (S1 will keep ⌘S = export until S7 lands). Principal Software Engineer/PM to confirm; if not accepted, swap the two shortcuts in AC1, AC15 and AC17.
- Whether theme files are also shareable/importable (assumed out of scope).
- The "(modified)" theme header rule in AC10 needs a product decision; the AC accepts either documented rule as long as it is tested.
- The default-template setting has only one valid value until S12 (gallery); the picker is shown disabled.
- Where Drafts are surfaced in UI (assumed only via recovery on launch and Open Recent) is not specified in the slice.
- Launch at login and a global hotkey from the reference are not in this slice.
