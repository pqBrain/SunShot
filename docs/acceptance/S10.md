# S10 — Crop & capture (screen, website URL) — acceptance criteria

Conventions: the crop is **non-destructive**: a `CropRect {x, y, width, height}` in whole content pixels (origin at
the top-left of the original image, y down) stored on the document (`EditorDocument.crop`, saved as `crop` in
`document.json`), never baked into the image. It is applied on the single render path (`Renderer.render(document:)`),
so preview and export agree and the original bytes are saved unchanged. Ratio presets = `Free | Original | 1:1 | 4:3 |
3:4 | 3:2 | 2:3 | 16:9 | 9:16`. S9 annotations stay in **uncropped** content pixels and are drawn shifted by minus the
crop origin, so they stay on the same image pixels whatever the crop. Screen capture uses ScreenCaptureKit
(`SCScreenshotManager`); website capture uses an offscreen `WKWebView` with a non-persistent data store. Capture code
lives in SunshotPlatform behind protocols (`ScreenCapturing`, `WebPageCapturing`), so tests use fakes or local HTML and
never touch the network or the real screen. Viewports: Desktop 1440×900, Laptop 1280×800, Tablet 834×1112, Phone
390×844 (CSS px). Menu: File ▸ Capture Area… ⌥⇧⌘4, Capture Window… ⌥⇧⌘5, Capture Website… ⌥⇧⌘L; Edit ▸ Crop… ⌥⌘C.

## S10-AC1 — Crop maths: clamping and rounding
Given an image of 1000×600
When a crop of (−20, −10, 300, 200), (900, 500, 300, 300) or (2000, 0, 10, 10) is clamped
Then the first becomes (0, 0, 280, 190), the second (900, 500, 100, 100) and the third is nil (nothing left)
And a fractional rect rounds to whole pixels inside the image, never below 1×1
Test level: unit

## S10-AC2 — Free handle drags
Given a crop (100, 100, 400, 300) on 1000×600 and the free ratio
When each corner and edge handle is dragged, including past the image edge and past the opposite edge
Then only the dragged edges move, the rect stays inside the image, never flips, and keeps at least 16 px per side
And dragging the interior moves the rect without resizing it, stopping at the image edges
Test level: unit

## S10-AC3 — Ratio presets and ratio-locked drags
Given a ratio preset (1:1, 4:3, 3:4, 3:2, 2:3, 16:9, 9:16 or Original)
When it is chosen, the crop becomes the largest rect of that ratio inside the current crop, centred on it
And when any handle is dragged afterwards the rect keeps the ratio (within 0.01), stays inside the image and keeps
its anchor (opposite corner, or opposite edge centred on the other axis)
Test level: unit

## S10-AC4 — Handle hit-testing
Given a crop rect and a grab tolerance
When a point is near a corner, near an edge, inside, or outside
Then the corner handle, the edge handle, `move`, or nothing is returned (corners win over edges)
Test level: unit

## S10-AC5 — Crop is rendered, the original is kept
Given 1000×600 content cropped to (100, 50, 400, 300)
When rendered at 1× and 2× with padding 0 and no shadow
Then the canvas is 400×300 (800×600 at 2×) and shows exactly those source pixels
And the document still holds the original 1000×600 image and its original bytes
And a document with no crop renders byte-identically to before S10
Test level: unit

## S10-AC6 — Crop is one undoable step; full-image crop means no crop
Given content with no crop
When Apply sets a crop, it is one undo entry "Crop Image"; undo restores the uncropped render
And a crop equal to the whole image is stored as no crop ("Remove Crop" when it removes one)
And applying the same crop again records nothing
And replacing or clearing the content, or starting a code snippet, drops the crop
Test level: unit

## S10-AC7 — Crop dialog flow
Given content cropped to R
When Crop… is opened, the draft is R on the full image size; changing the draft does not touch the document
And Cancel leaves the document unchanged; Reset sets the draft to the whole image with the Free ratio
And Apply records the draft as the crop; Crop… is disabled without image content and in Annotate mode
Test level: unit

## S10-AC8 — Tall images scroll in the crop dialog
Given the dialog area 720×520 points
When the image is 1000×600, the display fits it inside the area without scrolling
And when the image is 1440×16000 (a full-page website), it fills the width and scrolls vertically
And view points map to content pixels with the display scale both ways
Test level: unit

## S10-AC9 — Annotations stay on the same pixels after cropping
Given a rectangle annotation and a redaction at content pixels (300, 200, 100, 80) on 1000×600 content
When the content is cropped to (200, 100, 400, 300)
Then the rendered annotation and redaction cover output pixels (100, 100, 100, 80) of the cropped content
And Annotate mode pointer mapping returns uncropped content pixels (view → content adds the crop origin, and back)
And the canvas size, frame title bar, layout thumbnails and position projection use the cropped size
Test level: unit

## S10-AC10 — Crop is saved and reopened
Given a cropped document
When saved as a `.sunshot` package and reopened
Then the crop and the original media bytes round-trip unchanged
And a `document.json` without a `crop` key (older documents) opens uncropped, and an out-of-range crop is clamped or
ignored instead of failing
Test level: unit

## S10-AC11 — Website capture at a viewport width
Given a page and the Phone viewport (390×844)
When captured from local HTML (tests never use the network)
Then the picture is 390×844 points wide/tall (times the backing scale) and shows the page
Test level: integration

## S10-AC12 — Full-page website capture
Given a page 3000 px tall
When captured with Full page on
Then the picture is the whole page height (capped at 16,000 px), after scrolling through it so lazy content loads
Test level: integration

## S10-AC13 — Website address validation
Given typed text
When it is `example.com`, `https://example.com/a?b`, `http://localhost:8080` or `localhost:8080/x`
Then it is accepted as an http(s) URL (`https://` added when no scheme is typed)
And empty text, text with spaces, `file:///etc/hosts`, `javascript:alert(1)`, `data:text/html,…`, `ftp://x.com` and
`https://` with no host are refused with a clear message, without loading anything
Test level: unit

## S10-AC14 — Website capture delay, timeout and cancel
Given a capture in progress
When it takes longer than the timeout it fails with "The page took too long to load." and the document is unchanged
And Cancel stops it without a message and without changing the document; a cancelled capture finishing late changes
nothing
And a successful capture replaces the content as one undo step "Capture Website" with the PNG kept as original media
And the delay is limited to 0…10 s
Test level: unit

## S10-AC15 — Screen capture of an area or a window
Given Screen Recording is allowed
When an area (display points, top-left origin) or a window is captured
Then the content becomes the captured image as one undo step "Capture Screenshot", keeping the style (S15: when
image content is already open, the capture is added as the next screenshot instead — see S15-AC10)
And areas smaller than 8×8 points are ignored; the area's pixel size is its point size × the display scale
And the window list leaves out Sunshot itself and windows smaller than 40×40, sorted by app then title
Test level: unit

## S10-AC16 — Permission denied is explained, never a crash
Given Screen Recording is not allowed (or the user declines)
When Capture Area… or Capture Window… is chosen
Then nothing is captured, the document is unchanged, and an explanation with "Open System Settings" is shown
And other capture failures show a one-line alert
Test level: unit

## S10-AC17 — Menus, shortcuts and the optional global shortcut
Given the menu catalog
Then File has Capture Area… (⌥⇧⌘4), Capture Window… (⌥⇧⌘5) and Capture Website… (⌥⇧⌘L), Edit has Crop… (⌥⌘C),
with no shortcut clashes
And the global Capture Area shortcut is off by default, saved in Settings, and only registered when turned on
Test level: unit

## S10-AC18 — Capture and crop in the running app
Given the running, sandboxed app
Then Capture Area shows a dimmed overlay with a size label (Esc cancels), Capture Window lists windows, Capture Website
loads a real site (network client entitlement) with progress and Cancel, the first capture triggers the macOS Screen
Recording prompt, and the crop dialog's handles, ratios and scrolling work in Light and Dark with VoiceOver labels
Test level: manual

## S10-AC19 — Changing the global shortcut
Given Settings ▸ Capture Area from anywhere is on
When the Shortcut button is clicked and new keys are pressed
Then those keys start an area capture from any app (⌥⇧⌘4 is the default; Restore Default brings it back; Esc
cancels recording, and the current keys don't start a capture while recording)
And keys without ⌃ or ⌥ (or ⇧⌘), other than function keys, and macOS's own screenshot keys (⇧⌘3–6, with or without
⌃) are refused with the reason; keys another app already holds show "Another app is using this shortcut"
And the keys are saved in Settings; stored keys that are no longer allowed fall back to the default
Test level: unit

## S10-AC20 — After a shortcut capture: open in Sunshot or copy to the clipboard
Given Settings ▸ After a shortcut capture
When it is "Open in Sunshot", a shortcut capture opens in the editor as in S10-AC15
When it is "Copy to clipboard", the captured area is put on the clipboard as a PNG, ready to paste; Sunshot stays in
the background, the open document is unchanged, and a short "copied" bubble appears (announced to VoiceOver)
And a capture that is too small, not permitted or fails copies nothing (failures bring Sunshot forward to explain)
And File ▸ Capture Area… from the menu always opens in the editor
Test level: unit

## Open questions
- Where does the crop live? On the document (`EditorDocument.crop`, `DocumentManifest.crop`), not in `Project`: it
  belongs to one image, so themes, layout presets and bulk edit (which share the style across images) never carry
  it. **Decided.**
- Annotation coordinates under a crop: uncropped content pixels, shifted at render time, so changing or removing the
  crop never moves annotations relative to the image. Annotations outside the crop are clipped, not deleted.
  **Decided.**
- Video crop (spec §3.3 "works on video too") belongs to S13 (video content); the same `CropRect` applies.
- S16 changed two defaults: the shortcut is now on and copies with the default style (S16-AC1, S16-AC2); the
  raw "Copy to clipboard" choice below is unchanged. **Decided.**
- Global hotkey: implemented (S16: on by default), ⌥⇧⌘4 via the Carbon hot-key API (no Accessibility permission); the
  keys can be changed in Settings (S10-AC19). **Decided.**
- Copy-to-clipboard copies the raw captured area, not the styled export: it is for pasting a screenshot right away;
  beautifying is what "Open in Sunshot" is for. **Decided.**
- Area capture covers the display under the pointer; multi-display spanning selections are out of scope.
  **Decided.**
- Website capture output is at the screen's backing scale (2× on Retina); there is no separate capture scale.
  **Decided.**
