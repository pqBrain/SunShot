# S2 — Border & shadow — acceptance criteria

Conventions: radius is in content pixels at 1× and scales with export scale. Defaults (in `SunshotDefaults`): corner style = smooth, radius = 24 px, shadow = spread / medium, light offset = (0, +0.35) (light from above, shadow falls down). "Content shape" = the content rect after corner rounding.

## S2-AC1 — Inspector shows Border and Shadow sections
Given a document with content loaded
When the inspector is opened (⌘⌥E or the inspector toggle)
Then it contains collapsible sections "Border" and "Shadow", each with its own Reset button
And with no content loaded the sections are disabled and show no stale values
Test level: app-smoke

## S2-AC2 — Border defaults
Given a new document
When the border model is read
Then style = smooth, radius = 24 px
And the default render matches snapshot `s2-border-default`
Test level: snapshot

## S2-AC3 — Corner style variants render distinctly
Given content 400×300 and radius 40 px
When style is set to sharp, smooth and round in turn
Then sharp ignores the radius and renders square corners (corner pixel at (0,0) of the content is fully clipped = 0 px rounding)
And round renders a circular-arc corner of radius 40 px
And smooth renders a continuous (squircle-style) corner whose silhouette differs from round by ≥ 1 px at the 45° point, with the same bounding box
And each variant matches its snapshot
Test level: snapshot

## S2-AC4 — Radius range and clamping
Given the border radius control
When the value is set to −5, 0, 1, 200, 201 and 10 000 (typed or via model)
Then stored values are 0, 0, 1, 200, 200 and 200 respectively
And non-numeric typed text is rejected and the previous value is kept
Test level: unit

## S2-AC5 — Radius larger than half the content is limited visually
Given content 100×60 and radius 200 px
When rendered
Then the effective corner radius is min(radius, 30 px) (half the shorter side) with no artefacts, inverted corners or crash
And the stored model value remains 200
Test level: snapshot

## S2-AC6 — Radius control: slider and numeric field stay in sync
Given the radius slider (0–200) and numeric field
When the user drags the slider to 80 or types 80 in the field and presses Return
Then both show 80 and the preview updates
And dragging the slider produces exactly one undo entry for the whole drag (not one per tick)
Test level: unit

## S2-AC7 — Shadow modes and intensities
Given content on a solid backdrop
When shadow style is none, spread and hug, each with low, medium and high intensity
Then none renders no shadow pixels outside the content shape
And spread has blur radius larger than hug at the same intensity, and hug stays within 12 px of the content edge
And for each style the shadow's peak alpha is strictly ordered low < medium < high
And all 7 distinct combinations (none, plus spread and hug at each of 3 intensities) match their snapshots
Test level: snapshot

## S2-AC8 — Shadow follows the corner shape
Given a shadow is enabled and corner style round with radius 80 px
When rendered
Then the shadow silhouette is the rounded content shape (no rectangular shadow showing at the corners)
Test level: snapshot

## S2-AC9 — Light-source handle moves the shadow offset
Given the light-source preview with a draggable handle at its default position
When the handle is moved to the left of centre
Then the shadow offset moves to the right by a proportional amount and the preview updates
And the handle is clamped inside the preview circle (normalised offset length ≤ 1.0)
And dragging the handle to the exact centre yields a zero-offset (centred) shadow
Test level: unit

## S2-AC10 — Light-source offset scales with content and export scale
Given a light offset (0, 0.35) and canvases at export scale 1× and 2×
When both are rendered
Then the 2× shadow offset and blur in pixels are exactly 2× the 1× values (±1 px)
And the 2× render is visually identical in structure to the 1× render upscaled (SSIM ≥ 0.98)
Test level: snapshot

## S2-AC11 — Keyboard control of the light-source handle
Given focus is on the light-source handle
When the user presses arrow keys (step 0.02) or ⇧+arrow (step 0.1)
Then the offset moves accordingly, clamped to the circle
And VoiceOver reads "Light direction, x <value>, y <value>" and supports adjustable increment/decrement
Test level: app-smoke

## S2-AC12 — Per-section reset
Given border radius 90/round and shadow hug/high with a custom light offset
When "Reset" is pressed on the Border section
Then only the border returns to smooth / 24 px and the shadow is untouched
And pressing Reset on the Shadow section returns it to spread / medium / (0, 0.35) without touching the border
And Reset on a section already at defaults is a no-op that does not add an undo entry
Test level: unit

## S2-AC13 — Every border and shadow mutation is undoable
Given the document store
When style, radius, shadow style, shadow intensity, light offset and both resets are each applied
Then each creates exactly one undo entry with a descriptive name (e.g. "Change Corner Style", "Move Light Source", "Reset Shadow")
And undoing all and redoing all reproduces the same final model value (equatable) and the same render bytes
Test level: unit

## S2-AC14 — Settings persist across document save and import changes
Given border and shadow are customised
When content is cleared and a new image imported (S1 flow)
Then border and shadow settings are kept (they are style, not content)
And the new content is rendered with them
Test level: unit

## S2-AC15 — Transparent content and shadow
Given a PNG with a transparent cut-out (e.g. a rounded-corner screenshot with alpha) and shadow = spread / high
When rendered
Then the shadow derives from the content's alpha shape and not from its rectangular bounds
Test level: snapshot

## S2-AC16 — Preview/export parity with border and shadow
Given a non-default border and shadow
When preview and export are rendered at 1× and 2×
Then both pass through the single render entry point and are byte-identical at the same scale
Test level: unit

## S2-AC17 — Large image with shadow stays within budget
Given an 8000×8000 content with shadow = spread / high and radius 200
When exported at 1×
Then the output is 8128×8128 px, peak memory growth ≤ 1.5 GB and there are no clipped shadow edges
And the 4K-canvas render (3840×2160) with border+shadow completes in ≤ 500 ms median on Apple silicon
Test level: integration

## S2-AC18 — Light and dark inspector chrome
Given the Border and Shadow sections
When shown in Light and Dark system appearance
Then all labels, sliders and the light-source preview meet contrast ≥ 3:1 for controls and ≥ 4.5:1 for text
And the exported image is unaffected by appearance
Test level: snapshot

## S2-AC19 — Accessibility of border and shadow controls
Given the Border and Shadow sections
When inspected with VoiceOver and keyboard-only
Then every segmented option, slider and field has a label ("Corner style: smooth", "Corner radius, 24 pixels", "Shadow intensity: medium")
And all controls are reachable in a logical Tab order and operable with arrow keys / Space
Test level: app-smoke

## Open questions
- Whether shadow `hug` also applies when the content is fully opaque and radius = 0 (assumed yes).
- Exact blur and offset constants per intensity are design-owned; AC7 only fixes the ordering and hug extent (≤ 12 px). The Designer should supply final numbers for snapshots.
- Radius is in absolute pixels (not relative to content); confirm for very small images.
