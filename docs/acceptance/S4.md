# S4 — Canvas size & export options — acceptance criteria

Conventions: canvas size mode = `auto | ratio preset | exact-pixel preset | custom W×H`. Presets live in bundled JSON `canvas-presets.json` with fields `{id, group, name, ratioW, ratioH, pixelW?, pixelH?}`; groups: general, social, store. Scale options: `1×`, `2×`, `4K`, `6K`. "4K" and "6K" mean the long edge of the output is 3840 px and 6144 px respectively. Default export = PNG at 2×. Default scale/format values are in `SunshotDefaults`.

## S4-AC1 — Canvas size control and default
Given a new document with content
When the aspect/size control is read
Then it shows `Auto` as current value
And in Auto the canvas is content + 64 px padding on each side (identical to S1-AC6/AC7)
Test level: unit

## S4-AC2 — Preset JSON is valid and complete
Given the bundled `canvas-presets.json`
When it is loaded by the validator test
Then it contains the three groups general, social and store, each with ≥ 4 presets (≥ 25 in total)
And ids are unique, ratios are positive integers/decimals, names are non-empty
And every `store` preset has both `pixelW` and `pixelH` and `pixelW/pixelH` equals the ratio within 0.5 %
And the file contains no third-party trademark text other than neutral platform names used as group labels
Test level: unit

## S4-AC3 — Search presets
Given the preset popover
When the user types "square", "9:16", "  STORY ", "zzzz" and clears the field
Then results are the case-insensitive, whitespace-trimmed matches on name, group or ratio text
And "zzzz" shows the empty message "No sizes match" and an unfiltered list is restored on clear
Test level: unit

## S4-AC4 — Ratio preset fits content inside the canvas
Given content 1000×600 and the preset 1:1
When the canvas is computed
Then the canvas is square with side = max(content W, H) + 2×64 = 1128 px (the smallest canvas of that ratio that contains the padded content)
And the content stays centred and unscaled
And for 16:9, 9:16 and 4:5 the canvas ratio equals the preset ratio within 1 px rounding and the padded content always fits
Test level: unit

## S4-AC5 — Exact-pixel store presets export at exact size
Given each preset in the `store` group
When the document is exported at the preset's native scale
Then the output image is exactly `pixelW × pixelH` px for every store preset (verified by decoding the file)
And the content is scaled down (aspect-preserving) to fit inside the preset with at least the 64 px padding ratio maintained proportionally
Test level: integration

## S4-AC6 — Custom W×H input validation
Given the custom size fields
When the user enters (800, 600), (1, 1), (16384, 16384), (0, 100), (−5, 100), (20000, 100), ("abc", 100), and an empty field
Then 800×600, 1×1 and 16384×16384 are accepted
And values < 1 or > 16384 or non-numeric are rejected with an inline message "Enter 1–16384", the previous value is kept and no undo entry is created
And an empty field means Auto for that dimension
Test level: unit

## S4-AC7 — Custom size with one dimension left Auto
Given content 1000×600 and custom W = 1200, H = Auto
When the canvas is computed
Then the canvas is 1200 px wide and its height follows the ratio of the Auto canvas (1128×728) i.e. 774 px (rounded to the nearest integer)
Test level: unit

## S4-AC8 — Canvas size changes are undoable and restorable
Given Auto canvas
When the user selects preset 16:9, then custom 800×600, then Auto
Then each step is one undo entry ("Change Canvas Size"), and undo/redo restore exact values including the custom W/H
And the preview canvas rectangle updates immediately to the new ratio
Test level: unit

## S4-AC9 — Export format selection
Given the export options popover
When PNG, JPEG, HEIC or WebP is selected
Then the choice is stored in the document and shown in the read-only "Format" row as `.png`, `.jpg`, `.heic`, `.webp`
And WebP is offered only if `CGImageDestination` reports `org.webmproject.webp` as writable on the running OS; otherwise the option is hidden
Test level: integration

## S4-AC10 — Encoded files are valid for every format
Given a 1000×600 content image
When exported as PNG, JPEG (quality default 0.9), HEIC and (if available) WebP
Then each file decodes via ImageIO with the expected pixel size and type identifier
And JPEG output of a canvas with a transparent backdrop is flattened onto white (no black background) and a notice "JPEG doesn't support transparency" is shown in the popover
Test level: integration

## S4-AC11 — Scale options produce exact pixel dimensions
Given Auto canvas of 1128×728 (content 1000×600)
When exporting at 1×, 2×, 4K and 6K
Then output sizes are 1128×728, 2256×1456, 3840×2478 and 6144×3965 px respectively (4K/6K scale the canvas so the long edge equals 3840/6144, rounding the short edge to the nearest integer)
And the read-only "Resolution" row shows these dimensions before exporting
Test level: unit

## S4-AC12 — Scale never exceeds the supported pixel limit
Given a custom canvas 16384×16384 at 6K or at 2×
When export is requested
Then export is blocked with "This size is too large to export (max 16384 px per side)" or the scale is clamped, and the UI states which; there is no crash and no out-of-memory termination
Test level: unit

## S4-AC13 — Preview/export parity at every scale
Given a document with border, shadow and gradient backdrop
When rendered at 1×, 2×, 4K, 6K
Then each output equals the preview render function result for the same scale (byte-identical)
And the 4K output downscaled to the 1× size matches the 1× render with SSIM ≥ 0.98 (resolution-independent styling)
Test level: snapshot

## S4-AC14 — Filename template tokens
Given template `{TEMPLATE}_{SCALE}_sunshot_{DATE}`, template name "screenshot", scale 2×, now = 2026-11-17 08:19:05
When the file name is generated
Then the result is `screenshot_2x_sunshot_2026-11-17_08-19-05.png`
And scale tokens render as `1x`, `2x`, `4k`, `6k`
And `{WIDTH}` and `{HEIGHT}` render the output pixel size, `{RANDOM}` renders 6 lowercase alphanumeric characters (different on each call, deterministic with an injected generator in tests)
Test level: unit

## S4-AC15 — Filename template edge cases
Given templates `""`, `report`, `a/b:c`, `{UNKNOWN}`, `{DATE}{DATE}`, and a 400-character template
When the file name is generated
Then an empty template falls back to the default template
And characters `/ : \` are replaced with `-`
And unknown tokens are left as literal text
And repeated tokens are all expanded
And the base name is truncated to 200 characters so the full name stays within the 255-byte filesystem limit
And the extension always matches the selected format
Test level: unit

## S4-AC16 — Export button label reflects the current preset
Given scale 2× / PNG on Auto, then 4K / JPEG, then a store preset "iPhone 6.7"
When the toolbar is read
Then the primary button label is `Export 2× • PNG`, `Export 4K • JPEG` and `Export 1290×2796 • PNG` (store presets show their exact size) respectively
And the label is announced by VoiceOver in full
Test level: unit

## S4-AC17 — Export applies the chosen options and filename
Given format HEIC, scale 2×, template default
When the user presses ⇧⌘E and confirms
Then the save panel's suggested name follows S4-AC14 with `.heic`
And the written file has the dimensions from S4-AC11
Test level: integration

## S4-AC18 — Copy PNG ignores the file format choice but honours scale
Given format JPEG at 4K
When the user presses ⌘C
Then the pasteboard holds a PNG at the same pixel size as a 4K export (never a JPEG)
Test level: integration

## S4-AC19 — Render time and memory at 4K/6K
Given a 3712×2032 content image on Auto at 4K, and an 8000×8000 content image at 2×
When exported on Apple silicon (release build)
Then the 4K render completes in ≤ 500 ms median of 10 runs (excluding encoding)
And the 8000×8000 export at 1× (8128×8128 px) stays under 1.5 GB peak memory
And the 8000×8000 export at 2× (16256×16256 px, within the 16384 limit) either completes with peak memory ≤ 4 GB or is refused with the S4-AC12 message, never crashes
Test level: integration

## S4-AC20 — Accessibility of size and export controls
Given the size popover and the export options popover
When used with VoiceOver and keyboard only
Then the search field, preset grid items ("16:9 Widescreen, 1920 by 1080"), W/H fields, format and scale pickers all have labels
And the grid is navigable by arrow keys and selects with Return, Esc closes the popover
Test level: app-smoke

## Open questions
- Store preset list and exact pixel dimensions (App Store / Play) come from a data file the Architect or PM must supply; AC5 tests whatever is in the JSON.
- AC4 assumes the canvas grows (never shrinks the content) for ratio presets, whereas AC5 scales content to fit exact-pixel presets; confirm that ratio presets should not scale content.
- Maximum canvas side 16384 px is an assumption (Core Image / texture limit).
- JPEG default quality 0.9 and HEIC quality are assumptions; no quality slider is in scope.
- Whether `{TEMPLATE}` is always "screenshot" until the template gallery exists in S12 (assumed yes).
