# S12 — Device mockups & template gallery — acceptance criteria

Conventions: device mockups are **generic, Sunshot-drawn vector frames** — Phone, Tablet, Laptop and Monitor — in the
finishes Graphite, Silver, Sand and Sage. No product shapes, names or logos (no notch / island replicas; a lens is
a plain dot in the bezel). Device geometry is data: `Sources/SunshotCore/Resources/devices.json` lists finishes,
models (rounded-rectangle parts in device units, back to front, roles `shell | edge | bezel | detail | lens |
screen`, exactly one screen, a recommended media size and common capture sizes) and multi-device arrangements. The
catalog is validated when it loads. A document's device is `Frame.device = {model, finish, landscape,
arrangement}` (nil = none); a device replaces the S5 frame chrome, so the frame kind is `none` while one is set.
Content is **aspect-filled (centre-cropped) into each screen**; the primary screen is the laid-out content rect,
so device chrome grows an Auto canvas exactly like S5 frame chrome. Templates are document presets (canvas,
backdrop, corners, shadow, frame or device, placement — never content) in
`Sources/SunshotCore/Resources/templates.json`; the first is "Screenshot" (the plain new document).

## S12-AC1 — Bundled device catalog
Given the app bundle
When the device catalog loads
Then it has the models Phone, Tablet, Laptop and Monitor (one per category phone / tablet / laptop / desktop), the
finishes Graphite, Silver, Sand and Sage, and the arrangements Single, Pair, Trio, Laptop & Phone, Monitor & Phone
and Tablet & Phone
And every model has exactly one screen whose aspect matches its recommended media size within 1 %, and phones and
tablets can turn while laptops and monitors cannot
Test level: unit

## S12-AC2 — The catalog refuses bad data
Given device JSON with a malformed body, two screens or none, a part with zero size or a radius over half its
side, a colour that isn't opaque hex, a screen whose aspect doesn't match the recommended size, duplicate ids or
names, no Graphite finish, an arrangement with no or two primary slots, a primary slot that is offset or scaled,
an unknown model in a slot, or a first arrangement that isn't "single"
When it is decoded
Then decoding throws `DeviceCatalogError.invalid` and nothing is drawn from it
Test level: unit

## S12-AC3 — Device field is backward compatible
Given a new document, a document saved before S12 (no `device` key), and a device naming a model this version
doesn't know
When they are decoded and rendered
Then `Frame.device` defaults to nil, the encoded document has no `device` key, the default render stays
byte-identical to the S2 default snapshot, an unknown device decodes but draws no device (plain content), and a
document with a device round-trips through JSON and a saved `.sunshot` package unchanged
Test level: unit

## S12-AC4 — Content fills the screen, cropped not scaled
Given content of exactly a device's recommended size (Phone, 1080×2340)
When it is laid out on an Auto canvas
Then the content rect is the full content (no crop, 1:1 pixels)
And given content of another shape (e.g. 1600×1000 on a Phone) the screen is the largest rect of the screen's
aspect inside the content (461.5…×1000), centred, and content pixels stay 1:1 (the overflow is cropped evenly)
Test level: unit

## S12-AC5 — Device chrome grows the Auto canvas
Given Auto canvas, padding 64, Phone, content 1080×2340
When the canvas is computed
Then the frame box is the screen plus the device chrome scaled from device units (3 px per unit: 69 px left and
right including the side buttons, 60 px top and bottom) and the canvas is 1346×2588
And the same rule holds for every model and arrangement (screen + layout insets + padding), and the primary screen
is exactly `CanvasLayout.contentRect`
Test level: unit

## S12-AC6 — Device rendering
Given sample content on Phone (Graphite), Tablet landscape (Silver), Laptop (Sand) and Monitor (Sage)
When rendered
Then each draws its shell (finish gradient with an edge line), bezel, screen with the content, lens and its
buttons / hinge / stand, all as vector shapes, and matches its snapshot
Test level: snapshot

## S12-AC7 — Finishes recolour the device only
Given a Phone with content
When the finish changes from Graphite to Silver to Sand
Then the shell colour sampled at the device edge changes to the finish's colours while the pixels inside the
screen are identical in all finishes
Test level: unit

## S12-AC8 — Orientation
Given a Phone or Tablet
When Landscape is chosen
Then the device (and its screen) turns a quarter clockwise — width and height of the layout swap — and the
recommended size swaps sides
And for Laptop and Monitor the orientation control is hidden and setting landscape changes nothing (no undo entry)
Test level: unit

## S12-AC9 — Multi-device layouts
Given one image
When the arrangement is Pair, Trio, Laptop & Phone, Monitor & Phone or Tablet & Phone
Then every device of the arrangement shows the same content, aspect-filled into its own screen, in one render by
the single `Renderer.render` (no second drawing path), the primary device's screen is the content rect, the
arrangement grows the Auto canvas, and the output matches snapshots
And a fixed combination selects its primary model (Laptop & Phone → Laptop); choosing a model that a fixed
combination can't show falls back to Single
Test level: snapshot

## S12-AC10 — Devices move, tilt and cast shadows as one object
Given a device mockup with a layout preset (tilt) and the default shadow
When rendered
Then the whole device layout is transformed as one silhouette around the frame box centre (S6) and the shadow
follows the device's outline, and the output matches a snapshot
Test level: snapshot

## S12-AC11 — Preview and export parity
Given a document with a device
When it is rendered for the preview and exported at 1× and 2×
Then preview and export call the same `Renderer.render`, the 1× preview equals the 1× export pixel for pixel, and
the 2× export is exactly twice the canvas size
Test level: unit

## S12-AC12 — Device edits are undoable
Given a document with content
When the user picks a device, a finish, an orientation, a layout, or None
Then each is one undo entry ("Change Device", "Change Device Finish", "Change Device Orientation", "Change Device
Layout", "Remove Device"), an edit that changes nothing records nothing, picking a device sets the frame kind to
None and keeps the finish and (for turnable devices) the orientation, and picking a frame kind removes the device
Test level: unit

## S12-AC13 — Device suggestion from media size
Given media sizes
When a device is suggested
Then an exact capture size picks its device with confidence "exact" (1179×2556 → Phone portrait, 2752×2064 → Tablet
landscape, 3024×1964 → Laptop, 1920×1080 → Monitor)
And otherwise the device whose screen aspect is within 3 % (closest first, then the closest recommended size) is
picked with confidence "aspect" (393×852 → Phone, 1600×1000 → Laptop, 1280×720 → Monitor, 1560×720 → Phone
landscape)
And media matching no screen (1000×1000, 800×300) gets no suggestion
Test level: unit

## S12-AC14 — Suggestion in the editor
Given Settings ▸ "Suggest the device that matches imported images" is on (the default) and an image of a phone
capture size is imported
When the Device section is shown
Then it offers "This image fits a Phone" with Use, and Use applies the device as one undo entry
And no suggestion is shown when the setting is off, when a device is already set, for code snippets, or when the
image matches no device; the setting persists across launches
Test level: unit

## S12-AC15 — Bundled templates
Given the app bundle
When the template catalog loads
Then it validates against the gradient, wallpaper, layout-preset and device catalogs, the first template is
"Screenshot" and equals a new document, ids and names are unique Sunshot names, and there are at least 12
templates of which at least 8 show devices (single, pair, trio and each fixed combination)
Test level: unit

## S12-AC16 — The template catalog refuses bad data
Given template JSON with an unknown gradient, wallpaper, layout or device, a frame and a device together, a
backdrop with two kinds, an out-of-range padding, corner radius or canvas, a fixed combination with the wrong
model, a duplicate id or name, or a first template that isn't the plain document
When it is decoded
Then decoding throws `TemplateCatalogError.invalid`
Test level: unit

## S12-AC17 — Live gallery previews
Given the template gallery
When it opens with image content, with a code snippet, or with an empty document
Then every template's card is rendered by `Renderer.render` from the document the template would make (identical
pixels to rendering that document at the same scale) with the current content, or with sample content of the
template's recommended size when the document is empty, fitted to 240 px on the long side, off the main actor
Test level: unit

## S12-AC18 — Applying a template
Given a document with content, annotations, a frame title, export options and an applied theme
When a template is chosen
Then the style becomes the template's (canvas, backdrop, padding, corners, shadow, frame or device, placement)
as one undo entry "Apply Template <name>", the content, annotations, frame title and export options stay, the
theme header reads "No Theme", the gallery closes, and undo restores the previous style and theme
Test level: unit

## S12-AC19 — Default template
Given Settings ▸ Default template lists every template (the S7 value "Screenshot" selects the Screenshot template)
When a template is chosen there
Then File ▸ New, Start Over and the empty window at launch use that template, Start Over is enabled only when
the document differs from it, an unknown stored value falls back to Screenshot, and the choice persists
Test level: unit

## S12-AC20 — Documents carry the device
(S17-AC1 removed saved themes, which used to carry the device too; the default style still does, as part of its
project.)
Given a document with a device
When the document is saved and reopened
Then the reopened document shows the same device
Test level: unit

## S12-AC21 — Annotate stays off on devices
Given a document with a device mockup
When Annotate is offered
Then Annotate mode can't be entered (the toolbar button is disabled) because pointer mapping doesn't yet include
the screen crop; existing annotations still render on the primary screen, cropped with the content
Test level: unit

## S12-AC22 — Device section, gallery and menu in the running app
Given the running app with an image
When the user opens the Device section, chooses devices / finishes / orientation / layout, opens File ▸ Templates…
(⇧⌘T) or the toolbar's Templates button, and Settings
Then the controls work, VoiceOver reads "Device: Phone, selected", "Finish: Graphite, selected" and
"Template: Pocket Spotlight, …", the gallery sheet closes with Esc, and the Settings picker and toggle work
Test level: app-smoke

## Open questions
- Exact device proportions, finishes and template list are design placeholders; the UI/UX Designer should confirm.
- Per-device media in multi-device layouts ("replace all vs selected") — deferred, see decisions.
- Video templates and the All · Image · Video filter belong to S13.

### Decisions (S12 implementation, 2026-11-17)
- **Device lives in `Frame.device`** (not a new `FrameKind`): the S5 eight-frame picker stays as specified, the
  device is drawn by the same `FrameRenderer` call inside the S6 transform and shadow layer, and themes carry it
  as one more field.
- **Crop, don't scale:** content keeps 1:1 pixels in the primary screen; other shapes are centre-cropped. This
  keeps Auto exports sharp. Annotate is disabled for devices until pointer mapping includes the crop (AC21).
- **Multi-device scope:** the same content on every device of an arrangement (Single, Pair, Trio and three fixed
  combinations). Separate media per device is deferred.
- **Templates are a validated JSON schema**, not raw `Project` JSON, so every reference (gradient, wallpaper,
  layout, device) is checked at load and templates survive model changes.
- **Default template setting** stores the template id; the S7 value "Screenshot" still resolves by name.
